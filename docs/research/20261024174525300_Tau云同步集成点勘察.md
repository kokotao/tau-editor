# Tau 编辑器云存储集成点勘察报告

## 1. 结论摘要

- Tau 是 Tauri 2 + Vue3 + Pinia 桌面文本编辑器；编辑器入口集中在 `frontend/src/App.vue`（单文件应用壳），真正的文件读写/会话/外部变更逻辑已在 `services`、`stores` 与 Rust 命令层分层清晰。
- 文件打开/保存/自动保存/会话恢复/外部冲突处理均已具备可直接复用的“基线-比较-事务”模式；云同步应复用这些既有能力，而不是另起一套磁盘写入。
- 当前**没有**网络请求/账号/凭据存储/云同步配置位点。Rust 侧已依赖 `reqwest`（用于 GitHub 更新），但没有任何云 API 或密钥持久化；前端依赖中**没有 axios**，只有 `@tauri-apps/api` 与插件。
- 最适合插入云同步的最小改动点：在 `lib/tauri.ts` 新增一组 `cloudSyncCommands`；新建 `services/cloudSyncService.ts` + `stores/cloudSync.ts`；在 `App.vue` 的自动保存/会话保存/外部冲突处理三个关键路径挂接；在 `SettingsPanel` 增加“云同步”分类；在命令面板注册 `cloud.login` 等命令。
- 大文件/二进制预览已有明确边界（`workspaceService.ts:58-74`、`fileService.ts:179-194`），云同步白名单建议直接基于同一套判断，默认只同步文本可编辑内容，二进制/大文件仅做占位或显式排除。
- 文档规范采用 `docs/*` 时间戳命名（如 `docs/decision/20260921231903499_恢复库v2_app-data分文件存储决策.md`），本报告按约定落盘到 `/tmp/tau_cloud_sync_investigation.md`。

## 2. 本地文件模型 / 打开保存链路

### 2.1 Tab 模型（核心状态）

- `frontend/src/stores/tabs.ts:3-27`：`Tab` 包含 `filePath`、`fileName`、`language`、`isDirty`、`isUntitled`、`content`、`lastKnownModified`、`fileRevision`、`externalModifiedAt`、`largeFile*` 等字段。
  - `lastKnownModified` 记录最近一次与磁盘一致的修改时间，是外部冲突/云端对比的天然基线。
  - `fileRevision` 记录与磁盘一致时的 revision（`mtimeNs:size`），保存事务可用。
  - `externalModifiedAt` 已被外部变更但尚未合并的修改时间。
- Pinia store 默认不持久化（`tabs.ts:216-225`），会话由 `sessionService` 专门管理，避免把整个 tab 内容写进 localStorage。

### 2.2 文件服务

- `frontend/src/services/fileService.ts:28-45`：`FileService` 定义 `binaryPreviewExtensions`，并有 1 秒防抖自动保存的位点（`autoSaveTimer`/`autoSaveDebounceMs`）。
- `fileService.ts:80-122`：`openFile()` 打开文件 -> 读取内容 -> `tabsStore.addTab()` -> `editorStore.setContent()/markAsSaved()`。这是“本地打开”的单一入口，云同步“打开云端文件为新建本地标签”可复用它或在其后追加。
- `fileService.ts:130-177`：`saveFile()` 直接 `fileSystemStore.writeFileContent(filePath, editorStore.content)` 后 `updateTabDirty(false)`。注意：这个老实现没有 revision 校验，实际保存已逐步切换到 `tabService.saveTab()`（见 2.4）。
- `fileServiceOptimized.ts:46-116`：`loadFileOptimized()` 负责文件大小探测与分块加载/缓存（50MB、5 分钟 TTL）。云同步可基于同一路径做“本地磁盘文件 vs 云端内容”合并。

### 2.3 工作区与文件树

- `frontend/src/stores/workspace.ts:17-31`：`WorkspaceState` 含 `mode/currentWorkspacePath/currentWorkspaceName/recentProjects/recentFiles/initialized`；localStorage key 为 `text-editor-workspace`（`workspace.ts:23-25`）。
- `frontend/src/stores/fileSystem.ts:5-15`：`FileTreeNode` 基于 `FileEntry`，树形结构与目录刷新集中在 `refreshFileTree()`（`fileSystem.ts:75-115`）。云同步后本地文件树变化可直接调用该刷新，无需改树组件。

### 2.4 保存与自动保存（当前真实路径）

- `frontend/src/services/tabService.ts:246-323`：`saveTab()` 是保存主线：
  - 先检查 `externalModifiedAt`（246-254），冲突时拒绝保存；
  - 大文件在 Tauri 下走 `commitLargeFileRevision()`（262-265），否则分块写入；
  - 普通文件走 `fileSystemStore.writeFileContent()`（273）；
  - 保存成功后刷新 `lastKnownModified / fileRevision / externalModifiedAt`（284-291）。
- `frontend/src/App.vue:3518-3576`：`runAutoSave()` 自动保存：untitled 草稿写恢复库，有路径的脏标签调用 `tabService.saveTab(tab.id, { silent: true })`（3556）。云同步应在该函数成功保存本地文件后触发“上传变更”，或在 `saveTab()` 成功分支挂接，避免自动保存与上传双写竞争。
- `App.vue:3578-3587`：自动保存定时器由 `settingsStore.autoSaveInterval` 驱动；设置面板里有“自动保存”开关位（`SettingsPanel.vue:489-507`）。
- 存在不只一套历史文件服务：`fileService.ts` 的老 `saveFile()` 与 `tabService.saveTab()` 并存；云同步应统一收口到 `tabService.saveTab()` 或 `cloudSyncService` 包装，避免两套保存路径。

## 3. 外部修改冲突已有逻辑（可直接复用为云端三方合并）

### 3.1 决策函数

- `frontend/src/services/externalFileSync.ts:1-47`：
  - `ExternalFileSyncAction = 'noop'|'flag'|'reload'`（1）；
  - `ExternalFileSyncDecisionInput` 含 `isDirty / lastKnownModified / externalModifiedAt / observedModified`（3-10）；
  - `resolveExternalFileSyncAction()`（25-47）实现“脏标签只 flag、干净标签自动 reload、时间相同 noop”的三方判定，可直接推广为“本地缓冲版本 vs 磁盘版本 vs 云端版本”。
- `frontend/src/stores/fileConflicts.ts:5-81`：`FileConflictRecord`（path/kind/detectedAt/diskModifiedMs/diskSize/baselineModifiedMs）与 `flag()/find()/resolve()/retainOnly()/clear()`，是云端冲突提示 store 的现成模板。

### 3.2 事件监听与页面联动

- `frontend/src/services/workspaceWatcherService.ts:63-135`：Tauri 工作区 watcher（native 失败时退回轮询），`onChange()` 注册变更处理器。
- `frontend/src/App.vue:3120-3225`：`reloadTabContentFromDisk()` / `findTabByPath()` / `notifyExternalConflict()` 组装“磁盘 vs 编辑器”通知与重载。
- `App.vue:3249-3360`：`syncActiveTabExternalChanges()` 周期性轮询当前标签的文件信息并走 `resolveExternalFileSyncAction()`；`startExternalFileSync()` / `startExternalFileWatch()` 二选一建立监听。
- `App.vue:3903-3908,4468-4477`：冲突对话框（`ExternalChangeDialog`）与状态栏入口已就绪。云同步冲突可以通过同一条 `fileConflictsStore` 通道复用 UI，差异仅在于“变更来源”多一个 `cloud`。

### 3.3 Diff 只读对比

- `frontend/src/services/diffService.ts:48-76`：`DiffSide` 结构为 `{label, filePath?, content}`，`createDiffSession()` 强制 `readOnly: true` 并做 2MB/二进制守卫。
- `diffService.ts:151-236`：`loadWorkspaceFileDiffSession()`（本地磁盘 vs 编辑器内容）与 `loadGitDiffSession()`（HEAD vs 工作区）就是云端三方合并现成的“只读预览”底座，可新增 `loadCloudDiffSession()`。

## 4. 设置持久化 / 账号配置位点

### 4.1 设置 store

- `settings.ts:570-663`：`loadFromStorage()` / `saveToStorage()` 全部走 localStorage；**没有账号/云同步/网络字段**。
- `settings.ts:1113-1144`：`init()` 先 localStorage 再 `loadFromTauri()`，Tauri 侧目前只同步自动保存间隔。
- `settings.ts:1178-1196`：`saveSettings()` 注释明确“目前 Tauri 后端只存储了自动保存间隔，未来可扩展”。

### 4.2 设置面板

- `frontend/src/components/editor/SettingsPanel.vue:1092-1107`：分类列表为 `general / themes / editor / fileAssociations(仅 Windows) / updates / about`，“云同步”分类应插在这里。
- 各分类区块已按 `activeCategoryValue` 渲染（`SettingsPanel.vue:86,324,406,664,705,779`），新增云同步区块可保持同样结构，无需改整体布局。

### 4.3 i18n

- 单文件字典：`frontend/src/i18n/ui.ts`（非 vue-i18n）。
- `ui.ts:1`：`UiLanguage = 'zh-CN'|'en-US'`；`ui.ts:1560-1601`：`getXxxI18n()` 按语言返回文案对象。
- 设置面板文案集中在 `SETTINGS_PANEL_TEXTS`（`ui.ts:741-...`），命令文案集中在 `COMMAND_TEXTS`（`ui.ts:466`），新增云同步 key 需同时在 中英文两块补充。

## 5. Tauri / Rust 能力

### 5.1 运行环境判断

- `frontend/src/lib/tauri.ts:94-100`：`isTauriApp()` 通过 `'__TAURI_INTERNALS__' in window` 判断，纯浏览器 `npm run dev` 下返回 false；云同步应在此基础上下发“Web 版只读演示/不可登录”级别能力。
- 同类 fallback 已普遍存在：`settingsCommands.getAutoSaveInterval()`（lib/tauri.ts:993-1000）、`getBrowserDeviceInfo()`（lib/tauri.ts:1106-1124）。Web 版用 localStorage 同构后端（sessionService.ts:17,126）。

### 5.2 命令与能力清单

- `frontend/src-tauri/src/lib.rs:40-90`：`invoke_handler` 注册了读/写/列表/rename/大文件/恢复库/工作区 watcher/Git/搜索替换/LSP 等命令，**没有**任何云/网络/凭据命令。
- `frontend/src-tauri/Cargo.toml:19-...`：依赖 `reqwest`（JSON + rustls-tls + stream，用于 GitHub Release 更新）、`sha2`、`rusqlite`、`zip`、`notify` 等，后端已有 HTTP 能力但未承接云同步。
- `frontend/src-tauri/commands/settings.rs:45-...`：`check_github_update` 已用 `reqwest::Client` 访问 GitHub；可直接复用 HttpClient 模式做云 API 集成，但**必须新增**凭据存储模块（如 keyring / OS keychain），当前无任何明文密钥落盘。
- `frontend/src-tauri/capabilities/default.json:11-22`：当前权限只有 core 默认、event、window、dialog；做云同步 API 时前端可以直接 fetch/reqwest（WebView 网络权限天然可用），但如需 Tauri 侧代理必须更新 capabilities/自定义 permission。
- Tauri 插件：仅 dialog/fs/single-instance（Cargo.toml:22-24；lib.rs:56-58），没有 http-plugin、keychain-plugin；若新增网络功能，更稳妥的是走 Rust 命令层自己接管。

## 6. 前端 UI 入口

- 应用壳：`frontend/src/App.vue`（并非 router 分页）。`App.vue:39-114` 引入 Toolbar/FileTree/CommandPalette/StatusBar 等组件；`App.vue:4120-4513` 是主布局（Toolbar / 侧栏 / 正文 / StatusBar）。
- 命令面板：`frontend/src/services/commandRegistry.ts:1-286` 定义 `AppCommand`（id/title/category/shortcut/keywords/run）与 `createCommandRegistry()`；`App.vue:2733-2799` 用 `createLocalizedCommands()` 注册命令并刷新到 `commandStore`。云同步命令（`cloud.login/logout/syncNow`）应在此注册。
- 状态栏：`StatusBar` 在 `App.vue:4507`；外部冲突已通过状态栏提示（`App.vue:4468-4477`），云同步状态/上传中/失败提示可复用同款组件或增加一个云状态区。
- 文件树：`frontend/src/components/editor/FileTree.vue`；`App.vue:4152-4218` 显示 `FileTree` 或最近工作区。文件树右键/操作区是放置“同步此文件 / 云端状态徽标”的最自然位置（组件已支持 providerActions，见 FileTree.vue:291-300,318-345）。
- 标题栏：`App.vue:3956-4050` 已有导航/QuickOpen/CommandPalette 按钮，也适合放“云同步”一级入口。
- HTTP 客户端：**没有 axios/fetch 封装**。前端依赖只有 `@tauri-apps/*`、Vue、Pinia、Monaco、naive-ui、marked、mermaid、xlsx 等（frontend/package.json:12-38）。云同步若走前端 fetch，建议新增一个 `services/httpClient.ts`；若走 Rust 命令层，则不需要前端 HTTP 依赖。

## 7. 大文件 / 二进制预览边界（云同步白名单）

- `frontend/src/utils/fileTypes.ts:1`：`IMAGE_EXTENSIONS`（png/jpg/jpeg/gif/webp/svg/bmp/ico/avif/tif/tiff），`isImageFilePath()`（5-12）。
- `frontend/src/services/workspaceService.ts:58-74`：`LARGE_FILE_CHUNK_LOAD_THRESHOLD_BYTES = 12MB`、`BINARY_PREVIEW_EXTENSIONS = {pdf,doc,docx,xls,xlsx,db,sqlite,sqlite3}`，`isBinaryPreviewPath()` 统一判断。
- `frontend/src/services/fileService.ts:32-41,179-194`：另一套 `binaryPreviewExtensions` 与 `isBinaryPreviewTab()`；cloud 白名单必须与这两处保持同一集合，避免“本地可编辑但云端拒绝”或反之。
- `diffService.ts:44,60-77`：`DIFF_MAX_BYTES=2MB`、`looksBinary()` 基于 NUL/控制字符采样，云端合并落地前建议复用此守卫。
- **建议云同步白名单**：文本可编辑内容（可由语言检测/扩展名推断），默认排除图片/二进制预览/大文件（>12MB 或大文件会话），或仅记录“云端文件对象”元数据而不缓存内容。

## 9. Tau 侧云同步最小改动插入点建议（只读勘察产出）

按依赖顺序，最小闭环可拆四步：

1. **命令桥接层**：在 `frontend/src/lib/tauri.ts` 新增 `cloudSyncCommands`（如 `getAccountStatus`、`syncNow`、`listRemoteFiles`），Rust 侧在 `frontend/src-tauri/src/commands/` 新建 `cloud_sync.rs`（含 reqwest + keyring 凭据），并在 `lib.rs:40-90` 的 `invoke_handler` 注册。无 Tauri 环境时返回 Web fallback。
2. **服务与 store**：新建 `frontend/src/services/cloudSyncService.ts`（上传/下载/三方冲突决策，复用 `externalFileSync.ts:25-47` 的状态机）与 `frontend/src/stores/cloudSync.ts`（账号/同步状态/队列/冲突记录，模板为 `stores/fileConflicts.ts`）。
3. **关键路径挂接**：在 `App.vue:3518-3576` 自动保存成功分支、`App.vue:3433-3515` 会话保存、以及 `App.vue:3120-3225 + 3249-3360` 外部变更刷新处分别调用 `cloudSyncService`；保存成功后再推送，避免与本地 revision 基线冲突。
4. **UI 入口**：在 `SettingsPanel.vue:1092-1107` 增加 `cloud` 分类（区块样式复制 `updates` 区块），在 `commandRegistry.ts:1-286` 注册 `cloud.login/logout/syncNow`，并在 `App.vue` 标题栏/状态栏加一个同步状态位。
