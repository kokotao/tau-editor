# C# OmniSharp 应用私有托管核验

## 结论

OmniSharp v2.0.0 可以作为 Tau Editor 的应用私有语言服务器下载并启动，不需要用户把 `omnisharp` 或 `dotnet` 安装到系统 `PATH`。官方 macOS arm64/x64 发行包均为固定的 GitHub Release 资产，包内入口统一为 `OmniSharp`，格式为 `tar.gz`。

但是，只有 OmniSharp 发行包加 .NET runtime 只能证明 LSP 进程可以启动并完成 `initialize`。当工作区存在 `.csproj`/`.sln` 时，OmniSharp 还会通过 Roslyn BuildHost 查找 .NET SDK；只提供 runtime 会出现 `No .NET SDKs were found`，项目无法加载。因此 C# 的“IDE 级定义跳转/诊断”闭环必须再托管一个固定版本的 .NET SDK（建议与 OmniSharp v2.0.0 的 net10.0 构建匹配，固定 `10.0.100`），不能只把 runtime 标为完成。

## OmniSharp 固定资产

来源：GitHub `OmniSharp/omnisharp-roslyn` release `v2.0.0`（2026-09-18）。

| 平台 | 下载资产 | SHA-256 | GitHub asset id |
| --- | --- | --- | --- |
| macOS arm64 | `omnisharp-osx-arm64.tar.gz` | `dd2b16f64c42085cc27980376cb795b8ee80ba58af12e219f27c392b010913d4` | `571937133` |
| macOS x64 | `omnisharp-osx-x64.tar.gz` | `4096abe8595f37d3799c8fb25a4cb974ec77208453c7d1a91f99f1d83d25d94d` | `571937154` |

固定下载地址形式：

```text
https://github.com/OmniSharp/omnisharp-roslyn/releases/download/v2.0.0/omnisharp-osx-arm64.tar.gz
https://github.com/OmniSharp/omnisharp-roslyn/releases/download/v2.0.0/omnisharp-osx-x64.tar.gz
```

本机通过 GitHub Releases API 下载并重新计算 SHA-256，两个结果均与 release API 的 `digest` 一致。包内根目录包含：

```text
OmniSharp                 # Mach-O arm64/x64 apphost，带可执行权限
OmniSharp.dll
OmniSharp.deps.json       # .NETCoreApp,Version=v10.0
BuildHost-netcore/        # Roslyn MSBuild BuildHost
license.md
大量 Roslyn/NuGet/语言资源 DLL
```

因此安装清单应使用：

```text
serverId:       omnisharp
version:        2.0.0
archiveFormat:  tarGz
executablePath: OmniSharp
launchCommand:  ${runtime install directory}/dotnet
launchArgs:     [${install directory}/OmniSharp, --languageserver]
```

在现有 `ApplicationLspService` 的复合运行时契约中，等价配置是：`managedRuntimeId = dotnet-runtime`，OmniSharp 资产的 `launchArgs = ['--languageserver']`；服务会把已解析的 `OmniSharp` 绝对路径放在私有 `dotnet` 的第一个参数。

## .NET runtime 固定资产

## 真实启动与 initialize 验证

测试环境：Apple Silicon macOS，未依赖系统 `dotnet`，通过 `DOTNET_ROOT` 指向解压后的应用私有 runtime；启动时将 `PATH` 限制为 `/usr/bin:/bin`。

启动命令：

```text
DOTNET_ROOT=<private-runtime> <private-omnisharp>/OmniSharp \
  --languageserver --source <workspace>
```

空工作区收到有效响应：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "capabilities": {
      "textDocumentSync": 1,
      "workspace": {"workspaceFolders": {"changeNotifications": false}}
    },
    "serverInfo": {
      "name": "OmniSharp",
      "version": "2.0.0+Branch.master.Sha.972733863a27b48c56dc392001972952afadafa9.972733863a27b48c56dc392001972952afadafa9"
    }
  }
}
```

验证日志还明确显示：`DotNetPath set to <private-runtime>/dotnet`，说明 OmniSharp 使用的是应用私有 runtime，而不是 PATH 中的 dotnet。

## .NET SDK 缺口证据

使用同样的私有 runtime、同样的 LSP initialize 请求，并在工作区放置最小 `Test.csproj`，OmniSharp 能完成协议 `initialize`，但项目加载失败：

```text
Roslyn BuildHost ... could not load '.../Test.csproj'
Error while calling hostfxr function hostfxr_resolve_sdk2
No .NET SDKs were found.
```

这不是 OmniSharp tarball 损坏，而是它的 MSBuild BuildHost 需要 SDK。因而不能把“runtime + OmniSharp initialize 成功”误报为 C# 项目导航完成。

官方 .NET 10.0.0 SDK 候选（还需下载后计算 SHA-256，再写入安装 manifest）：

| 平台 | URL | 官方 SHA-512 |
| --- | --- | --- |
| macOS arm64 | `https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.100/dotnet-sdk-10.0.100-osx-arm64.tar.gz` | `0ee9c774f9c63601844619b67d6ca829d70fa26b9949b808e801380c35edb12e4c9418baf8e2ef8ba1dc6dc7d307dbf5830fb0f4f97666032a391c5c097ee607` |
| macOS x64 | `https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.100/dotnet-sdk-10.0.100-osx-x64.tar.gz` | `595c3c661a705a256f52e03e3aeeb86753ad6f9aa3d59f487304cdbbb744a39f4e3fa6445a60cded6bc78e12f51d52ed5a183ea70a0560b96bed61fb83958f81` |

SDK asset 的安装入口同样是解压目录根部的 `dotnet`。为避免把用户项目的 `global.json` 或系统 SDK 误带入，启动 C# 时应设置私有 `DOTNET_ROOT`，并把 SDK 目录置于该 runtime 根目录的私有安装目录中；验证后再决定是将 SDK 作为 `dotnet-runtime` 的 companion dependency，还是单独注册 `dotnet-sdk` 并让 OmniSharp runtime descriptor 同时准备两者。

本机下载 arm64 SDK 后计算得到的 SHA-256 为：

```text
71b3815ef8d83a6bbebf8627a56639600193f22d4ea6a6de2f71855c4b3e63fd
```

本机下载 x64 SDK 后计算得到的 SHA-256 为：

```text
d8fd6e3f2e393cad300794d43ae26d01f9db31356c95381bcfb9d3d7f66d187e
```

官方 metadata 中的 SHA-512 与本机计算值一致。解压后的私有 SDK `dotnet --info` 显示 SDK `10.0.100`、runtime `10.0.0`，与 OmniSharp v2.0.0 构建目标匹配。

再次以 `DOTNET_ROOT=<private-sdk>`、`PATH=/usr/bin:/bin` 启动 OmniSharp，并在工作区放置最小 `Test.csproj`，日志显示：

```text
Successfully loaded project file '.../Test.csproj'.
Update project: Test
```

随后同一 LSP 会话返回 `initialize` 结果，且没有 `No .NET SDKs were found`。这证明 C# 项目加载需要 SDK，但 SDK 也可以完全放在 Tau Editor 应用私有目录中，不需要用户安装系统 .NET。

## 对 Tau Editor 的实施建议

1. 不要把 C# manifest 的 `status` 改为 verified，直到 OmniSharp、runtime、SDK 三者均有固定 URL/SHA-256，并通过包含 `.csproj` 的真实工作区 `initialize` + `textDocument/definition` 或诊断请求。
2. 保持所有资产在应用私有 `lsp-servers/<server>/<version>` 下，绝不写入系统 PATH；启动前由应用注入 `DOTNET_ROOT`、`DOTNET_ROOT_ARM64`/`DOTNET_ROOT_X64`（按平台需要）以及私有 SDK 路径。
3. SDK 下载包约 230 MB（arm64 HEAD 的 `Content-Length` 为 `229936839`），应继续使用按需下载；不要默认塞入 DMG，避免普通用户安装包被无条件放大。
4. 断网时复用已安装版本；下载、SHA-256 校验、解压和 manifest 更新继续沿用现有原子安装流程。

另外，OmniSharp 的 macOS 资产是自带 .NET apphost 的 Mach-O 文件。无 `DOTNET_ROOT` 且 PATH 被限制为 `/usr/bin:/bin` 时直接执行会得到：

```text
You must install .NET to run this application.
.NET location: Not found
```

所以启动命令必须是私有安装目录中的 `OmniSharp`，并注入 `DOTNET_ROOT=<dotnet-sdk installDir>`（arm64 同时设置 `DOTNET_ROOT_ARM64`）。不能把私有 `dotnet` 当作 command 再把 `OmniSharp` 当作第一个参数；dotnet CLI 会将 apphost 路径解析为不存在的命令。现有 Node 的“runtime command + script arg”复合启动逻辑不能直接复用于 OmniSharp。
