# Go/gopls 应用私有资产核验

## 结论

Tau Editor 可以在不要求用户安装 Go 或把 `gopls` 加入系统 PATH 的情况下提供 Go 语言服务。资产必须同时携带 `gopls` 和 Go SDK：`gopls` 在分析模块、加载标准库和执行 workspace 查询时仍会调用 Go 工具链；只打包单个 `gopls` 二进制会把安装负担转移给用户。

建议将以下两个归档作为 `v0.6.7` 的 GitHub Release 资产。发布后，manifest URL 使用对应的 immutable URL：

```text
https://github.com/kokotao/tau-editor/releases/download/v0.6.7/tau-gopls-0.23.0-darwin-arm64.tar.gz
https://github.com/kokotao/tau-editor/releases/download/v0.6.7/tau-gopls-0.23.0-darwin-x64.tar.gz
```

归档内固定入口为 `tau-gopls`，它设置私有 `GOROOT`、`GOPATH`、`GOMODCACHE`、`GOCACHE` 和 `GOTOOLCHAIN=local`，随后执行同一归档内的 `gopls`。因此安装器的 `executablePath` 与 `launchCommand` 都应填写 `tau-gopls`，`launchArgs` 填写 `['-mode=stdio']`。

## 真实启动验证

从 arm64 归档解压后，在 `PATH=/usr/bin:/bin`（不依赖系统 Go）环境执行：

```text
tau-gopls version
golang.org/x/tools/gopls v0.23.0
```

随后以 `tau-gopls -mode=stdio` 发送 LSP `initialize` 请求，进程在 20 秒内返回约 5.6 KB 的 JSON-RPC 响应，包含 `hoverProvider`、`definitionProvider`、`referencesProvider` 和 `documentSymbolProvider` 等能力；stderr 为空。x64 原始二进制也已在本机以 `arch -x86_64` 完成相同 initialize 握手。

## 构建与发布

可复核构建脚本位于 [`scripts/lsp/build-gopls-bundles.sh`](../../scripts/lsp/build-gopls-bundles.sh)。脚本会：

1. 下载并校验 Go `1.27.1` arm64/amd64 SDK；
2. 从不可变模块版本 `golang.org/x/tools/gopls@v0.23.0` 构建两个 Darwin 目标；
3. 将 SDK、gopls 和 `tau-gopls` wrapper 打入确定性 `tar.gz`；
4. 打印 Release 资产 SHA-256。

本地验证归档暂存于 `/tmp/tau-gopls-bundles.UBrZvb/`，上传 Release 后必须重新从 GitHub 下载并运行 manifest 网络校验，确认线上文件的 SHA-256 与本记录一致。若重新构建归档，gzip/tar 元数据或 Go 编译器版本变化会导致 SHA-256 变化，必须同步更新 manifest，禁止沿用旧值。

## 依赖和限制

- 该资产覆盖 macOS arm64 与 x64；Windows/Linux 需要分别构建对应 Go SDK 与 gopls 包。
- `go env` 和模块下载路径已经指向应用私有目录；没有网络时，已安装的 workspace 可以继续启动，首次分析新依赖仍可能需要项目自己的模块缓存或网络。
- Go SDK 体积较大（每个压缩包约 84–89 MB），适合按需下载；不建议把两个架构包直接塞进 DMG。
- Release 资产正式上传前，registry/manifest 不应标记 Go 为已验证；上传后再把 URL、SHA-256、`archiveFormat: tarGz`、`executablePath: tau-gopls` 和 `launchCommand: tau-gopls` 写入清单。
