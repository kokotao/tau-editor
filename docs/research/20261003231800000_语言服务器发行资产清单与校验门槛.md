# Tau Editor 语言服务器发行资产清单与校验门槛

## 结论

应用不得把 `latest`、未锁定版本、未核实 SHA-256 或来源不明的下载地址写入内置 registry。`scripts/lsp/lsp-assets.manifest.template.json` 只作为发布前模板；运行校验脚本时，任何空值、占位 hash、mutable URL 或缺少启动参数都会失败。

## Node 运行时

TypeScript Language Server 和 Pyright 共享应用托管的 Node runtime。Node `22.22.2` 的 macOS arm64/x64 官方 tarball SHA-256 已从同版本官方 `SHASUMS256.txt` 核对为：arm64 `db4b064726706928f5a49a1891c3c35f4a79cb8c4e974b242c274a3e6a8b9000`，x64 `12a6d463d9d6258dfbd0b141500bdcf51b17893e7c4da45f408736bf749e08ba`。发布机仍必须重新下载验证，不能复用 npm 的 SHA-1/SHA-512 字段。

## 发布前命令

1. 将模板复制为发布清单，并给每一条资产补充不可变 URL、64 位 SHA-256、实际归档格式和启动参数。
2. 对每一条资产执行静态校验：

   ```bash
   node scripts/lsp/verify-manifest-assets.mjs --manifest scripts/lsp/lsp-assets.manifest.json
   ```

3. 在网络可用的发布机执行下载并重新计算 SHA-256：

   ```bash
   node scripts/lsp/verify-manifest-assets.mjs \
     --manifest scripts/lsp/lsp-assets.manifest.json \
     --verify-network \
     --download-dir /tmp/tau-lsp-assets
   ```

4. 校验通过后，才允许把生成的 manifest 复制给 Rust trusted registry；模板中的 `pending-sha256`/`blocked` 资产不得进入生产 registry。

## 当前阻塞项

- 当前后端仅支持 `binary` 和 `zip`，无法直接安装 rust-analyzer 的 gzip、Node 的 tar.gz 或 npm tarball；需要扩展归档格式或在发布流水线生成统一 zip bundle。
- gopls、JDT LS 和 OmniSharp 还没有可安全写入的固定官方 macOS arm64/x64 独立资产，因此本次不伪造 URL/hash。
- 完整无痛体验需要同时托管 Node、Java、.NET 等 runtime；项目 SDK（Go/Cargo/JDK/.NET SDK）缺失时仍应允许编辑并显示能力降级提示。
