# 语言服务器无痛交付方案

## 决策

Tau Editor 不要求普通用户手动安装 TypeScript、Python、Go、Rust、Java、C# 语言服务器，也不把语言服务器写入系统 PATH。应用采用“应用私有目录 + 按需下载 + 校验后启动 + PATH 高级覆盖”的模式。

## 当前问题

当前实现的 `languageServerRegistry.ts` 只提供命令名，Rust Supervisor 直接按 PATH 启动外部进程。因此开发机可以通过 npm、brew、go、rustup 等安装后工作，但普通用户下载 DMG 后仍需要自行准备语言服务器和运行时，这不符合无痛交付目标。

## 用户体验目标

1. 用户打开 TypeScript、Python、Go、Rust、Java 或 C# 项目时，不需要打开终端，也不需要 sudo。
2. Tau Editor 在后台准备对应语言服务；首次准备时只显示一次轻量进度，准备完成后自动启动。
3. 后续启动复用本地缓存；更新采用新目录安装，校验成功后原子切换，失败自动回滚。
4. 无网络时继续使用已缓存版本；从未准备过且无法联网时，编辑器仍可编辑，并明确显示“语言服务尚未准备”，不阻塞编辑。
5. 高级用户可以在设置中指定 PATH 或自定义可执行文件，但这不是普通用户的必需步骤。

## 为什么不能只下载六个服务器

- TypeScript Language Server 和 Pyright 主要以 Node 生态交付，因此托管方案需要同时管理 Node 运行时和 npm 包。
- gopls 的项目分析依赖 Go 工作区和 Go 工具链上下文。
- rust-analyzer 需要 Rust 标准库源码，并且项目分析通常需要匹配的 Rust toolchain。
- Eclipse JDT LS 至少需要 Java 21 运行时。
- OmniSharp 需要可用的 .NET SDK/运行时。

因此，真正的无痛方案是“语言服务 + 最小匹配运行时”的按语言资产包，而不是只下载一个服务器可执行文件。

## 分层实现

### 第一层：应用托管运行时

新增 `ManagedLspProvisioner`，负责：

- 根据平台和架构选择资产；
- 下载到应用私有数据目录，例如 macOS：`~/Library/Application Support/Tau Editor/lsp/<server>/<version>/`；
- HTTPS 下载、SHA-256 校验、临时目录写入、原子 rename；
- 文件权限和 macOS 可执行权限；
- 版本清单、失败重试、缓存清理和回滚；
- 通过绝对路径启动，不修改用户 PATH。

### 第二层：运行时环境注入

启动 LSP 时由应用为进程注入必要环境变量：

- Node：`PATH` 指向应用私有 Node；
- Java：`JAVA_HOME` 指向应用私有 JRE/JDK；
- .NET：`DOTNET_ROOT` 指向应用私有运行时；
- Rust/Go：指向应用私有工具链和标准库目录。

### 第三层：回退策略

解析顺序固定为：

1. 已安装且版本兼容的应用私有语言服务；
2. 用户显式配置的自定义路径；
3. 系统 PATH；
4. 轻量正则 fallback。

## 资产和许可证

发行包不默认塞入全部语言资产，避免首包过大。资产按语言首次使用下载，并在设置页显示版本、来源、许可证和缓存大小。每个资产都要在仓库中保留 manifest、SHA-256 和 NOTICE；不能使用未经锁定的“latest”二进制直接启动。

## 分阶段交付

1. macOS arm64/x86_64：实现 TypeScript、Python、Rust 的按需托管，验证 DMG 实地体验。
2. macOS：补齐 Go、Java、C# 及其运行时资产。
3. Windows/Linux：补充平台资产和签名校验。
4. 发布流水线生成 manifest、checksum 和 NOTICE，并对资产做可复现构建/下载验收。

## 不采用的方案

- 不在安装器中静默执行 npm、pip、go install、rustup、brew 或 dotnet install；这些依赖用户环境、权限和网络，失败原因不可控。
- 不把语言服务器复制到系统目录或修改全局 PATH。
- 不把远程代码分析作为默认方案；源代码隐私和离线使用是编辑器的基础要求。
