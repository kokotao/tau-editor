# 决策：可取消搜索会话与替换预览提交模型

- 时间：2026-09-22 06:56
- 状态：已采纳
- 关联：`docs/report/20260922065412122_v0.3.3_W5_可取消搜索与替换预览交付报告.md`

## 背景

旧实现中 `search_workspace` 是同步命令，大工作区搜索无法中断；`apply_workspace_replace` 直接按文件 `replace_all` 覆盖写，用户无法确认命中范围，失败后也没有撤销路径。

## 决策

1. 搜索以 `searchId` 作为会话标识，由后端 `SearchSessionRegistry` 登记取消令牌。
   - 取消是协作式的：搜索在遍历目录、读取文件、逐行扫描三处检查令牌。
   - 取消后返回已扫描到的部分结果并置 `cancelled: true`，不抛错，避免前端丢失已完成的工作。
   - 会话 300 秒超时清理；重复 searchId 返回 `SEARCH_IN_PROGRESS`，失效 searchId 返回 `SEARCH_EXPIRED`。
2. 替换分两阶段：预览（只读）与提交（写盘）。
   - 预览冻结每个文件的 revision 与命中数量，命中用 `相对路径#序号` 标识。
   - 提交必须携带 previewId，且同一 previewId 只能使用一次；提交后自动失效，避免旧计划重复执行。
   - 提交时逐文件复核 revision，不一致则记为 `conflict` 并跳过，不写盘。
3. 命中范围不可重叠。
   - 命中按行收集并跳过零长度匹配，因此同一行内的命中天然有序不重叠。
   - 同一行多个命中按从后往前替换，保证字节偏移不失效。
4. 撤销采用“替换前内容 + 写入后 revision”的副本。
   - 单文件上限 1 MiB、单次上限 8 MiB，超限文件标记 `undoable: false`。
   - 撤销同样走 revision 校验，外部改动时跳过并计入 `conflicts`。
5. 前端在替换/撤销后不静默覆盖编辑内容。
   - 干净标签从磁盘重载；脏标签标记外部冲突并提示，交由用户选择。

## 备选方案与取舍

| 方案 | 未采纳原因 |
|---|---|
| 直接中断搜索线程 | Tauri 命令运行在线程池，强制中断会遗留锁与半写状态，风险高于协作式取消 |
| 预览保存字节偏移 | 文件在预览后被外部修改时偏移会失效，改为保存 revision + 命中序号，提交时重新计算 |
| 全局事务提交替换 | v0.3.3 明确不做跨文件事务，跨文件部分失败会阻塞整批结果，逐文件结果更可解释 |
| 用磁盘备份文件实现撤销 | 会产生额外临时文件与清理责任，内存副本配合 revision 校验已足够覆盖 2 MiB 以内的搜索范围 |

## 影响

- 搜索命令签名变更（新增 `searchId` 参数），前端调用已同步更新。
- 新增两个后端注册表（搜索会话、替换预览/撤销），均带超时清理，异常退出不会长期占用内存。
- 旧命令 `apply_workspace_replace` 保留用于兼容，但不再是前端路径。
