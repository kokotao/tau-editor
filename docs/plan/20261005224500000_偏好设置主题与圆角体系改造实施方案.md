# 偏好设置主题与圆角体系改造实施方案

> 本文是实施前方案，当前仅完成只读分析与方案落盘，未修改业务代码。用户确认后再进入实现。

**目标：** 移除偏好设置中的“浅色 / 深色 / 系统”主题模式概念，改为仅按主题风格驱动整套界面背景、面板颜色与组件圆角，并让内置主题、主题市场和偏好设置页面保持一致。

**架构：** 保留主题包 JSON 的兼容读取能力，但把“用户选择的主题”收敛为 `themeSkin`/活动主题包；由当前主题风格解析出背景、面板、文字、强调色和 UI 圆角，再统一写入根节点 CSS 变量。现有 `light/dark` 仅作为旧配置和主题包分支的兼容数据，不再作为偏好设置的用户操作项。

**技术栈：** Vue 3、Pinia、TypeScript、Naive UI、CSS 自定义属性、Vitest。

---

## 一、现状与边界

### 当前实现

- `frontend/src/components/editor/SettingsPanel.vue`
  - 通用区同时展示主题模式按钮和 10 个明暗主题色板。
  - 主题市场区已有 UI 颜色和圆角设置，但圆角仅为 0–12 的整数滑块。
- `frontend/src/stores/settings.ts`
  - `EditorSettings.theme` 为 `light | dark | system`。
  - `themeSkin` 只决定 CSS skin 类，`resolvedTheme` 仍由 `theme + prefers-color-scheme` 决定。
  - `applyTheme()` 负责把主题颜色、UI 覆盖和圆角写入 `document.documentElement`。
- `frontend/src/utils/themeResolver.ts`
  - `resolveThemeState()` 同时解析 `theme`、系统偏好和 `themeSkin`。
- `frontend/src/utils/themePackage.ts`
  - 主题包已经支持 `colors.bgApp`、`colors.panelBase` 和 `modes.light/dark`。
  - 圆角位于 `ui.radius`，当前只接受 0–12 的整数。
- `frontend/src/services/themeMarketplaceService.ts`
  - 主题包 `theme` 可带背景色。
  - `palette` 明确禁止 `bgApp` 和 `panelBase`，需要调整。
- `frontend/src/App.vue` 与 `frontend/src/assets/workbench-theme.css`
  - 页面、顶栏、侧栏、编辑区、设置页均通过 `--bg-app`、`--panel-base`、`--radius-ui*` 等变量读取主题。

### 本轮不做

- 不重写 Monaco 主题规则体系。
- 不改变主题市场远程地址、缓存策略和下载安全边界。
- 不移除主题包旧 JSON 字段；保留兼容导入与导出。
- 不处理本轮之前已经存在的 `App.vue`、`FileTree.vue` 等无关脏改动。

## 二、目标行为

### 1. 主题模式改为主题风格

- 偏好设置中删除“浅色 / 深色 / 系统”三段式主题模式控件。
- 通用设置只展示主题风格列表；每个主题风格本身携带完整背景色、面板色、文字色和强调色。
- 用户点击主题风格后，立即切换：
  - 应用根背景；
  - 顶栏、状态栏、资源区、编辑器和偏好设置页面背景；
  - 面板、浮层、标签、边框和语义色；
  - 主题包提供的 Monaco 基底主题（如有）。
- 偏好设置不再跟随系统明暗变化自动切换。

### 2. 偏好设置背景跟随当前配色

- 偏好设置页面默认使用当前主题风格的 `bgApp/panelBase`，不再写死 Nocturne 深色背景。
- 主题风格切换后，偏好设置页面实时更新背景和控件表面色。
- 主题市场安装/应用的主题包也能覆盖 `bgApp/panelBase`。
- 如果主题包缺失背景字段，按当前内置主题风格回退，不覆盖已有安全默认值。

### 3. 圆角适配绝大部分界面

- 圆角从“单一 0–12px 整数”升级为“全局基础半径 + 分类细节半径”。
- 全局基础半径建议范围：`0–24px`，支持 `0.5px` 步进或 CSS 小数值。
- 分类变量至少覆盖：
  - `--radius-control`：输入框、下拉、按钮、复选框；
  - `--radius-card`：设置卡片、主题卡片、市场卡片；
  - `--radius-panel`：主工作区、侧栏、设置页、抽屉；
  - `--radius-tab`：编辑器标签；
  - `--radius-dialog`：弹窗、命令面板；
  - `--radius-badge`：标签、状态徽标。
- 默认由基础半径派生分类值，用户可展开高级设置后对分类值进行无极细调；分类值始终受 `0–24px` 安全范围约束。
- 旧 `cornerRadius/cornerRadiusPreset` 配置自动迁移：旧基础值作为新基础半径，分类值缺失时按派生规则补齐。

## 四、建议的数据契约

### 主题包 UI 扩展

```json
{
  "ui": {
    "radius": {
      "base": 8,
      "control": 7,
      "card": 12,
      "panel": 14,
      "tab": 8,
      "dialog": 16,
      "badge": 999
    }
  }
}
```

兼容规则：

- `radius: 8` 继续表示基础半径 8px。
- 新结构字段缺失时按基础半径派生。
- `badge` 的 `999` 表示胶囊形，不参与普通半径上限截断；其他分类值限制在 `0–24px`。
- 主题包内分类圆角只提供建议值；用户设置优先。

### 用户设置迁移

```ts
{
  "theme": "system",
  "themeSkin": "deep-ocean",
  "cornerRadius": 6,
  "cornerRadiusPreset": "standard"
}
```

迁移后：

```ts
{
  "themeSkin": "deep-ocean",
  "cornerRadius": 6,
  "cornerRadiusPreset": "standard",
  "cornerRadii": {
    "base": 6,
    "control": 4,
    "card": 8,
    "panel": 10,
    "tab": 6,
    "dialog": 12,
    "badge": 999
  }
}
```

旧 `theme` 字段可以继续写回以兼容旧版本，但新版本不再让它驱动系统主题变化。

## 六、风险与回滚

- **风险：** 旧版本 `theme` 仍可能被外部脚本或旧数据读取。处理方式是保留字段读取和兼容写回，但停止将其作为新的用户交互源。
- **风险：** 主题包圆角结构扩大后，第三方主题包可能含非法或过大的值。处理方式是严格白名单、范围归一化和缺省回退。
- **风险：** 全局圆角变量影响范围较大。处理方式是先增加分类变量并保留旧变量别名，逐个替换宿主样式，配合组件单测和截图回归。
- **回滚：** 代码层面可按 Task 3/4 反向回退；数据层面保留旧 `theme/cornerRadius` 字段，旧版本仍可读取基本设置。
