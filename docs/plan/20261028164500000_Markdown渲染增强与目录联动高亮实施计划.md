# Markdown 渲染增强（分享/预览）与编辑器目录联动高亮 实施计划

> 需求：
> ① 分享的文件在线浏览的 Markdown 文档需支持流程图、表格、折叠块、代码等渲染；
> ② Tau 编辑器 Markdown 目录可以随编辑器和预览滑动高亮显示。
>
> 编写：2026-10-28 ｜ 范围：`lizi-learning-admin-pro`（分享页 + 云文档预览弹窗）、`tau-editor`（目录联动）

---

## 一、需求拆解与现状

| 编号 | 需求 | 现状 | 缺口 |
| --- | --- | --- | --- |
| M1 | 分享页 Markdown 支持**流程图** | 仅 `markdown-it` + highlight.js，mermaid 代码块原样输出为代码；项目已有 `src/utils/markdown-diagram.ts`（mermaid@8）仅供博客文章详情使用 | 分享页 / 云文档预览弹窗未接入后渲染；`ensureMermaidInitialized` 是模块级一次性初始化，公开页无法单独用 `securityLevel: 'strict'` |
| M2 | 支持**表格** | `markdown-it` 默认 preset 已启用 table 规则，分享页已有 `.share-content :deep(table)` 样式 | 需回归确认（表格在折叠块/窄屏下的横向滚动）；补窄屏与表头样式一致性 |
| M3 | 支持**折叠块** | `md` 以 `html: false` 构造，源码里的 `<details>` 会被转义成文本 | 需要一个安全的折叠块语法（不打开 raw HTML） |
| M4 | 支持**代码** | 已有 `highlight()`（highlight.js）+ 语言标签 + 行号（code 分支）；`pre.hljs` 无复制按钮 | 基本满足；本轮补「复制代码」与语言标签一致性（低成本增强，列 P2） |
| M5 | Tau 编辑器 Markdown 目录**随编辑器/预览滑动高亮** | `ContextRail.vue` 的「文档大纲」只渲染、可点击跳转（`@navigate`），无当前项高亮、无自动跟随；预览区标题已带 `data-source-line`（`markdownRenderService.renderMarkdown`） | 需要 active line 数据源（编辑器视口 + 预览滚动）+ 高亮态 + 自动滚动到可见 |

## 二、决策（评审用）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 折叠块采用 `::: details 标题` 容器语法（自实现 markdown-it 规则，零新依赖），**不打开 raw HTML** | 分享页是公开内容，`html:false` 是既有安全边界；自生成 `<details>/<summary>` 既能满足折叠需求，又不引入 HTML 注入面 |
| D2 | 流程图用既有 `markdown-diagram.ts` 在 `v-html` 更新后后渲染；公开分享页强制 `securityLevel: 'strict'`，云文档 owner 预览同样 strict | mermaid `loose` 允许 HTML label/点击回调，公开页不可接受；把 `ensureMermaidInitialized` 改成「配置变化即重新 initialize」，避免全局一次性初始化互相污染 |
| D3 | 语法错误的 mermaid 图**降级为原代码块**并给一行「图形语法无法渲染」提示，不抛错、不白屏 | 公开页可能渲染他人写的坏语法 |
| D4 | 表格保持 markdown-it 默认规则，本轮只做样式与窄屏横向滚动回归 | 不引入插件依赖 |
| D5 | 分享页与云文档预览弹窗（R4 新组件）共用同一套渲染增强 | 两处都基于 `renderMarkdownResult`，抽在同一处才能不漂移 |
| D6 | 目录联动采用「active line」单一状态：编辑器视口首行 / 预览区当前标题的 `data-source-line` / 用户点击目录项，三者都写入同一个 `activeOutlineLine` | 只有一条状态源，避免编辑器与预览互相抢高亮；映射逻辑（line → 大纲项）抽成纯函数便于单测 |
| D7 | 高亮对**所有大纲类型**生效（heading/class/function/key/selector），Markdown 之外的代码大纲同样受益；只在 `ContextRail` 可见时计算 | 通用实现不增加复杂度，顺带修复代码大纲无当前位置的问题 |
| D8 | 自动滚动「跟随」带抑制：用户手动滚动/悬停大纲列表后 3s 内不自动滚；点击目录项立即写 activeLine 并高亮 | 跟随滚动不能抢用户的滚动意图 |

## 三、实现方案

### 3.1 分享页 Markdown 渲染增强（admin-pro）

**`src/utils/share-render.ts`**
1. 新增 markdown-it 容器规则（`md.block.ruler.before('fence', ...)`）识别：

```
::: details 可选标题
**任意 markdown**（含代码块、表格、标题）
:::
```
输出 `<details class="md-details"><summary>标题</summary><div class="md-details__body">…</div></details>`；
`:::details`（无空格）同样识别；标题缺省为「详情 / Details」；未闭合的容器按普通段落降级（不吞后续内容）。
2. 确认 table 规则启用（默认 preset），并为表格补 `.md-table-wrap` 类需要的窄屏滚动（可在渲染后由组件包一层，或在 CSS 用 `display:block;overflow:auto`）。
3. 保留既有安全设置：`html:false`、link_open 强制 `target=_blank rel="noopener noreferrer nofollow"`、图片白名单。

**`src/utils/markdown-diagram.ts`**
- `ensureMermaidInitialized(config)` 改为「与上次生效配置不同的 JSON 才重新 initialize」，支持同一 SPA 内 strict/loose 并存；
- 新增可选 `onError`/降级：渲染失败时给 host 标记 `data-mermaid-error="1"` 并恢复原始文本（保留代码块外观）。

**`src/views/lizi/blog/public/share/index.vue`**
- `markdownHtml` 变化后 `nextTick` + `renderMarkdownDiagramsFromNode(contentRef, { mermaidConfig: { securityLevel: 'strict', theme: 'default' } })`；
- 补 CSS：`.md-details`（边框/箭头/内边距）、`.mermaid`（居中、溢出滚动、失败态）、表格窄屏横向滚动；
- 渲染后重算 TOC 位置（现有 scroll spy 依赖 offsetTop，图形渲染会改变高度 → 需在渲染完成后触发一次重测）。

**`src/views/system/cloudDoc/components/CloudDocPreviewDialog.vue`（R4 预览弹窗）**
- 同一套 mermaid 后渲染 + details/表格样式（scoped），保持与分享页一致的阅读体验。

### 3.2 Tau 编辑器目录联动高亮（tau-editor）

**新增 `src/services/scrollSpyService.ts`（纯函数，可单测）**
```ts
pickActiveOutlineIndex(items: Array<{ line: number }>, activeLine: number): number
// 返回最后一个 line <= activeLine 的下标；全部大于时返回 0；空数组返回 -1

pickActiveSourceLine(headings: Array<{ line: number; top: number }>, scrollTop: number, offsetPx: number): number
// 预览：取「top - offsetPx <= scrollTop」的最后一个标题的 line；没有则取第一个，空数组返回 0
```

**`EditorCore.vue`**
- `scroll-change` 事件负载增加 `topLine`（`editor.getVisibleRanges()[0]?.startLineNumber ?? 1`）与 `bottomLine`（可选），保持既有字段不变（纯增量，不影响预览比例同步）。

**`MarkdownPreview.vue`**
- 渲染完成后在预览容器内按文档顺序取 `h1..h6[data-source-line]`，记录 `{ line, top }`（`offsetTop` 相对滚动容器）；
- `handlePreviewScroll` 里用 `pickActiveSourceLine` 计算当前标题行并 `emit('active-line', line)`（节流到 rAF）；
- 内容/尺寸变化（ResizeObserver 或 nextTick）后重测标题位置。

**`App.vue`**
- 新增 `activeOutlineLine`（ref）与两条写入路径：`handleEditorScrollChange`（`topLine`）、预览 `@active-line`；
- 切换标签/文档内容变化时重置；
- 把 `:active-line="activeOutlineLine"` 传给 `ContextRail`；
- `handleContextNavigate(line)` 里同步写入 `activeOutlineLine`（点击立即高亮）。

**`ContextRail.vue`**
- props 增 `activeLine?: number`；computed `activeIndex = pickActiveOutlineIndex(outline, activeLine)`；
- 当前项加 `.context-outline-item--active`（左侧主色条 + 主色文本 + `aria-current="true"`）；
- `watch(activeIndex)` → `scrollIntoView({ block: 'nearest' })`，抑制规则见 D8（列表 hover/focus/手动滚动后 3s 内不滚）。

实施中新增的两条设计决定（已写入交付报告 §四）：
1. **折叠块内标题不进 TOC/不生成锚点**——闭合 `<details>` 内元素布局不可见，会带偏 scroll spy 与目录跳转；标题仍照常渲染。
2. **`renderMarkdownDiagramsFromNode` 返回值改为 `{ rendered, failed, total }`**——参数签名不变，用于统计降级数量；仓内既有调用点均忽略返回值。
