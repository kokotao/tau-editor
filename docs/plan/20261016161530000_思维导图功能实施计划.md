# 思维导图功能实施计划

> 最后更新：2026-10-16 17:26（Asia/Shanghai）

**目标：** 在 Tau Editor 中交付独立、可保存的思维导图文档，并通过格式适配层逐步支持 `.taumap`、`.xmind`、`.mm`、`.mmap` 及可识别的 `.map` 等主流来源，先完成可靠的树结构编辑、画布导航和基本交换，再扩展为覆盖多数日常场景的 XMind 类功能。

**架构：** 新增版本化 `.taumap` 文档和独立画布分支；所有外部格式先经过扩展名/魔数/内容探测，再由适配器转换到统一 Canonical MindMap Model。复用现有 tab、文件读写、保存冲突及未保存草稿恢复。地图领域模型、结构校验、布局、历史记录、画布交互、格式适配和导入导出分层，避免继续扩大 `App.vue` 业务复杂度，也不改写 Monaco/Markdown 的现有路径。

**技术栈：** Vue 3、TypeScript、Pinia、Tauri 2 通用文本文件 API、SVG/HTML 交互画布、Vitest、Playwright。现有依赖未提供专用思维导图组件；第一阶段先验证 SVG 自绘能否满足验收，新增依赖须由性能/交互 spike 证明必要性。

---

## 1. 实施约束与集成点

当前实现的主要扩展点：

- `frontend/src/App.vue`：集中编排工作台、命令及 active tab 渲染；仅新增 mindmap 判断与独立编辑分支，不把画布细节写进该文件。
- `frontend/src/stores/tabs.ts`：tab 有路径、语言、内容、dirty 状态；地图文档继续走保存管线，必要时增加明确的 `documentKind`，不要仅靠伪造语言模式识别。
- `frontend/src/services/workspaceService.ts`、`frontend/src/services/tabService.ts`：新建、打开、保存、另存为和文件类型识别。
- `frontend/src/services/sessionService.ts`：未保存恢复；地图序列化数据可跟随 tab 草稿恢复，但 `.taumap` 文件仍是正式保存来源。
- `frontend/src/services/commandRegistry.ts`、`frontend/src/services/keybindingService.ts`、`frontend/src/i18n/ui.ts`：新建命令、导出命令、快捷键和中英文命令文本。
- `frontend/src/services/markdownRenderService.ts`：已有 Mermaid mindmap 渲染；只加回归覆盖，不改为可编辑模式。
- `frontend/src/services/mindmap/formatRegistry.ts`：格式、版本、扩展名、魔数、读写能力、损失项和测试夹具注册表。
- `frontend/src/services/mindmap/fileFormatDetector.ts`：扩展名 + 文件头 + XML/JSON/ZIP 内部条目探测；处理未知、歧义和损坏结果。
- `frontend/src/services/mindmap/mindmapAdapter.ts`：适配器接口、Canonical 模型转换、能力报告和导入错误分类。
- `frontend/src/services/mindmap/importExportService.ts`：导入预览、损失报告、另存为/导出、临时文件和失败回退。

预计 Rust/Tauri 后端无需新增文件，MVP 复用文本文件 API 与现有对话框。如果后续确需新增后端代码文件，必须在文件头加入调用方要求的作用描述、作者 Albert_Luo、邮箱和创建日期注释。

## 3. 阶段任务与完成定义

### 阶段 0：数据契约与文件生命周期

- [ ] 定义 `format: 'tau-mindmap'`、`schemaVersion`、稳定节点 ID、root/child 顺序规则及错误分类。
- [ ] 定义 Canonical MindMap Model、`sourceFormat/sourceVersion/saveMode`、格式能力报告和有损字段报告。
- [ ] 实现格式注册表与探测器：优先检查魔数/内容，再使用扩展名；支持 `.taumap`、ZIP 容器、`.mm` XML、Markdown/OPML，并将歧义 `.map` 标记为待选择。
- [ ] 先为解析/序列化/结构校验写单测：往返一致、悬空 ID、重复 ID、父子引用不一致、环、损坏 JSON、未知 schema。
- [ ] 实现 `.taumap` 原生新建/打开识别；普通 `.json` 继续走 Monaco 文本模式；外部格式打开后默认进入导入预览，不原地覆盖。
- [ ] 让新地图复用保存、另存为、dirty、外部修改冲突和 session recovery，不绕开现有管线。
- [ ] 运行相关单测、类型检查与前端构建。

完成定义：空地图能被创建、另存为 `.taumap`、关闭并重新打开；错误文件不会被静默改写。

### 阶段 1：核心树编辑闭环

- [ ] 实现主题新增子节点/同级节点、编辑文本、复制、删除和顺序调整的领域命令。
- [ ] 删除父节点的影响有确认；root 删除有明确的替换/重置流程；所有结构操作可撤销/重做。
- [ ] 拖放命令校验祖先关系，拒绝成环；父子引用和 sibling 顺序保持一致。
- [ ] 用单元测试覆盖每类命令的 before/after、undo/redo 和非法输入不变更状态。
- [ ] 实现键盘创建、改名、删除、树序导航；输入框、Monaco、对话框聚焦时不抢键。

完成定义：全键盘可完成新增、改名、重排、删除、撤销和重做，节点不丢失且 dirty 状态准确。

### 阶段 2：画布与布局

- [ ] 为中心思维导图结构实现布局纯函数，测量节点文本并保证不同语言、换行下连线位置正确。
- [ ] 实现 SVG 节点/连线，节点选中、内联编辑、拖放提示、画布平移、缩放、适配内容和重置视口。
- [ ] 实现折叠/展开、基础主题色、长文本与 Unicode；视口状态与节点正文历史分开处理。
- [ ] 增加大纲视图和画布/大纲选择同步，确保焦点可见、可达。
- [ ] 以 200 节点 E2E fixture 验收；建立 1k/5k/10k 基准脚本或 fixture，按目标机器结果确认性能阈值。

完成定义：鼠标与键盘均可导航与编辑，普通交互不出现明显卡顿；画布完整适配且地图数据不因折叠/视口操作变化。

### 阶段 3：交换与分享

- [ ] 将 Markdown/OPML 作为普通适配器接入统一 Import/Export Pipeline；解析限制在支持的标题、列表和 outline 结构，不执行 HTML 或链接内容。
- [ ] 导入先解析到临时 Canonical 文档并校验，展示格式/版本/支持等级/损失报告，成功后再创建或替换地图；失败时文档、选择和撤销历史保持不变。
- [ ] Markdown/OPML 导出保留文本、层级和顺序；PNG 导出完整地图，可选择透明/纯色背景。
- [ ] 建立 `.mm` 适配器并验证树、文本、链接、备注的双向交换；建立 `.xmind` 读取 spike，覆盖 XMind 8 与 Zen/Workbook 的识别分支。
- [ ] 检查 PNG 大尺寸内存与画布裁切，导出期间给出进度或失败提示。
- [ ] 增加导入/导出成功、失败、Unicode、长图和覆盖确认 E2E。

完成定义：Markdown 导入导出层级无损；PNG 在外部查看器中完整显示整张地图。

### 阶段 4：XMind 类增强

- [ ] 增加多工作表/主题和结构布局（逻辑图、组织结构图、树形图），先扩展 schema 与迁移测试。
- [ ] 增加备注、链接、标签、优先级/图标标记、边界/概要和独立关系线。
- [ ] 增加主题模板、节点样式、搜索筛选和搜索结果定位。
- [ ] 增加 SVG/PDF/打印输出及相应错误与安全测试。
- [ ] 每个功能先定义可逆编辑/导出的语义，再加入领域命令、历史测试和 E2E。

完成定义：功能支持矩阵清晰，节点树编辑与关系线/概要/标注的语义不混淆；保存和导出往返不丢已支持字段。

### 阶段 5：格式兼容与发布验收

- [ ] 为 `.xmind`、`.mmap`、`.mm`、`.map` 具体厂商/版本建立格式支持矩阵，记录扩展名、魔数/内部条目、读写能力、可逆字段、损失项和测试样本。
- [ ] 对 `.xmind` ZIP、`.mmap` 包和其他归档格式建立真实小样本、损坏包、路径穿越、符号链接、附件超限和压缩炸弹边界测试；导入数据永不执行。
- [ ] 对 XML 格式关闭 DTD/外部实体/网络访问；对无法判定的 `.map` 提示用户选择具体格式或明确不支持，不允许静默改写。
- [ ] 只有通过兼容矩阵后才将某个“格式 + 版本”列入正式支持；否则保持为实验性/只读/不支持。
- [ ] 验收无障碍、键盘、主题对比、窄屏、普通编辑器回归与性能指标。

完成定义：发布说明准确标注支持的地图格式/版本、导入有损项与不支持能力；常规编辑器路径无回归。

## 5. 风险、隔离与回滚

| 风险 | 控制措施 | 回滚/降级 |
|---|---|---|
| `App.vue` 编排复杂导致普通编辑器回归 | 地图组件独立，渲染入口只按 `.taumap`/明确 documentKind 分流 | 移除地图入口与 document type 分支；保留已有文本路径 |
| 图模型、拖放和撤销历史状态不同步 | 领域操作为纯命令；每条操作做前后态、非法态和 roundtrip 测试 | 暂停结构化高级操作，允许以大纲模式编辑并安全另存 |
| 恢复库容量有限或正式文件解析失败 | `.taumap` 文件为主来源，恢复库仅临时草稿；版本化解析和安全失败 | 原文件保留，提供打开副本/原始文本查看，禁止静默覆盖 |
| 大地图布局卡顿或内存过高 | 分级基准、隐藏折叠分支、按需布局；必要时做视口渲染优化 | 对超大图提示性能限制，先关闭高级装饰/关系渲染 |
| 外部格式版本漂移或字段损失 | 适配器注册表、格式/版本矩阵、损失报告、默认导入 `.taumap` | 关闭对应适配器，保留 `.taumap`、Markdown、PNG 功能 |
| `.map` 扩展名冲突 | 魔数/内容探测，无法判定时让用户选择或只读 | 不注册通用 `.map` 写入器，禁止静默覆盖 |
| ZIP/XML/二进制解析风险 | 资源上限、路径校验、拒绝 symlink/加密包、禁用 XML 外部实体 | 禁用对应格式入口，原文件只读查看 |
| 快捷键与 Monaco/输入框冲突 | 按 active document 和 focus target 分派按键；E2E 覆盖地图与文本切换 | 用户可关闭地图快捷键或回退到显式工具栏操作 |

## 6. 管理件

- 决策记录：独立 `.taumap` + 版本化 JSON；Canonical MindMap Model + Adapter Registry；首期树模型和自动布局；Mermaid 保持只读预览；外部格式默认导入为 `.taumap`。
- 任务看板：阶段 0（格式探测/原生存储）→ 1 → 2 → 3（统一导入导出）为 MVP 依赖链；阶段 4 与 5 在数据契约和适配器接口稳定后进入。
- 风险清单：App.vue 集成范围、数据迁移/保存安全、格式版本漂移、`.map` 歧义、画布性能、快捷键与 ZIP/XML 导入安全。
- 本计划是实施基线；实现时若实际 Tauri 文件能力、现有保存流程或性能基准与假设不符，应先更新对应任务范围与验收，不静默改变用户可见格式承诺。
