# IDEA 级代码导航实施计划

制定日期：2026-10-03
适用版本：Tau Editor 0.6.4 当前代码基线

## 1. 目标

把当前“逐行正则 + 已打开模型”的轻量导航升级为真实项目语义能力，覆盖：

- 跳转到定义、声明、实现和类型定义。
- 查找所有引用、Peek References、引用结果分组与逐项跳转。
- 悬浮类型、签名、文档和诊断信息。
- 重命名、代码操作、补全、参数提示、格式化。
- 文档符号、工作区符号、调用层级和问题面板。

目标是达到跨语言的 IDE 级基线，不承诺一次性复制 IntelliJ IDEA 的全部语言专属插件能力。

## 2. 当前基线与关键决策

当前实现位于 `frontend/src/lib/monaco/setupMonaco.ts` 和 `frontend/src/services/codeNavigationService.ts`：

- 通过正则识别类、接口、函数和方法。
- 只查找当前及其他已打开的 Monaco 模型。
- Hover 的引用数量是全文正则计数，不是语义引用。
- 当前没有 LSP 客户端、JSON-RPC 通道、语言服务器进程管理或引用列表 UI。

关键决策：

1. 不继续扩展正则解析器来承担项目级语义分析。
2. Monaco 只负责编辑器渲染和 Provider 适配；语义分析交给语言服务器。
3. Tauri/Rust 负责语言服务器进程、工作区会话、JSON-RPC 转发、崩溃恢复和权限边界。
4. 保留现有正则 Provider 作为无语言服务器时的 fallback。
5. 先完成 TypeScript/JavaScript 端到端闭环，再扩展其他语言。

## 3. 推荐架构

```text
Monaco Editor
  │  model sync / providers / commands
  ▼
frontend/src/services/lsp/
  │  Tauri invoke + event/channel
  ▼
Tauri Rust LSP Supervisor
  │  每个 workspace + language 一个会话
  ▼
外部语言服务器（stdio JSON-RPC）
  ├─ TypeScript/JavaScript: typescript-language-server
  ├─ Python: pyright-langserver
  ├─ Rust: rust-analyzer
  ├─ Go: gopls
  ├─ C/C++: clangd
  ├─ Java: Eclipse JDT LS
  └─ C#: OmniSharp 或 Roslyn LSP
```

### 3.1 Rust/Tauri 层

建议新增：

- `frontend/src-tauri/src/lsp/mod.rs`
- `frontend/src-tauri/src/lsp/manager.rs`
- `frontend/src-tauri/src/lsp/process.rs`
- `frontend/src-tauri/src/lsp/protocol.rs`
- `frontend/src-tauri/src/commands/lsp.rs`
- `frontend/src-tauri/src/models/lsp.rs`

核心职责：

- 探测服务器可执行文件和版本。
- 按 `workspaceId + languageId` 启动、复用、停止服务器。
- 使用 `tokio::process::Command` 管理 stdin/stdout。
- 处理 `Content-Length` JSON-RPC 帧、请求 ID、通知和响应。
- 服务器崩溃后有限次数重启，失败后通知前端降级。
- 将诊断、进度、日志和服务器状态通过 Tauri event/channel 推送到前端。
- 不允许工作区配置直接执行任意 shell 命令；服务器路径、环境变量和启动参数需要白名单。

建议命令/事件：

- `lsp_start_session`
- `lsp_send_request`
- `lsp_send_notification`
- `lsp_stop_session`
- `lsp_session_status`
- `lsp:message`
- `lsp:diagnostics`
- `lsp:state`

### 3.2 前端 LSP 层

建议新增：

- `frontend/src/services/lsp/lspClientManager.ts`
- `frontend/src/services/lsp/tauriLspTransport.ts`
- `frontend/src/services/lsp/languageServerRegistry.ts`
- `frontend/src/services/lsp/documentStore.ts`
- `frontend/src/services/lsp/pathUri.ts`
- `frontend/src/services/lsp/monacoLspBridge.ts`
- `frontend/src/stores/lsp.ts`

需要集中处理：

- `file://` 绝对路径 URI；未保存文件使用 `untitled://` 并保持映射。
- Monaco 1-based 行列与 LSP 0-based 行列的转换。
- LSP 使用 UTF-16 character offset，不能直接把 JS 字符串索引当列号。
- `didOpen`、增量 `didChange`、`didSave`、`didClose` 生命周期。
- 编辑事件去抖、请求取消、请求超时和服务器初始化状态。
- 当前 tab、其他打开 tab、未打开文件之间的内容同步。

## 4. 现有代码接入点

- `frontend/src/lib/monaco/setupMonaco.ts`：保留编辑器基础配置，移除/降级正则 Definition/Hover Provider，接入 LSP Bridge。
- `frontend/src/components/editor/EditorCore.vue`：创建模型时传递真实 `filePath`，维护 `tabId → DocumentUri` 映射。
- `frontend/src/App.vue`：工作区切换、当前 Tab、打开文件和导航定位是 LSP 生命周期入口。
- `frontend/src/services/workspaceRuntimeService.ts`：复用 `workspaceId/rootPath/relativePath`。
- `frontend/src/services/workspaceWatcherService.ts`：复用文件变更事件，转发 `didChangeWatchedFiles`，避免重复扫描。
- `frontend/src/services/commandRegistry.ts`：新增定义、引用、Peek、重命名、实现、调用层级命令。
- `frontend/src-tauri/src/lib.rs` 与 `commands/mod.rs`：注册 LSP 状态和命令。
- `App.vue` 现有打开文件并定位行列的逻辑可复用为 Location 跳转处理。

## 5. 分阶段实施与验收

### P0：通道和生命周期

- 建立 Rust Supervisor、JSON-RPC stdio 通道、Tauri streaming event/channel。
- 建立 workspace + language 会话表。
- 完成 URI、位置和版本转换。
- 完成 `didOpen/didChange/didSave/didClose`。
- 服务器不可用时自动回退当前轻量 Provider。

验收：服务器启动/停止、崩溃重启、工作区切换、关闭文件、未保存内容同步均有单测和日志。

### P1：TypeScript/JavaScript 闭环

- 接入 `typescript-language-server --stdio`。
- 完成 Hover、Definition、References、Rename、Diagnostics、Document Symbols。
- 支持未打开文件的 Location 跳转。

验收：打开包含 `package.json/tsconfig.json` 的工作区，在两个未必打开的文件间验证 F12、Shift+F12、F2、诊断和 Outline。

### P2：引用结果和 IDE 导航 UI

- 新增 `ReferenceResultsPanel.vue`。
- 按文件分组、显示行预览、支持点击定位、取消请求、结果截断提示。
- 增加导航历史 Back/Forward、Peek Definition、Peek References。
- 将命令接入右键菜单、命令面板和快捷键。

验收：同一符号跨 100+ 文件查找引用，结果可取消、可定位、不会阻塞编辑输入。

### P3：多语言扩展

建议顺序：Python/Pyright → Go/gopls → Rust/rust-analyzer → C/C++/clangd → Java/JDT LS → C#。

验收：每种语言至少有一套真实 fixture，覆盖 definition、references、hover、rename、diagnostics；服务未安装时显示可操作引导并回退。

### P4：发行和完整 IDE 能力

- 系统 PATH 探测和版本兼容提示。
- 可选 sidecar 打包、平台签名、checksum、升级策略和 NOTICE/许可证。
- 补全、代码操作、格式化、语义高亮、Inlay Hints、调用层级和类型层级。
- 增加性能指标：首个响应、索引耗时、内存、请求取消率、崩溃重启次数。

## 6. 服务器安装策略

第一阶段优先探测用户系统 PATH，避免首版安装包体积和许可证复杂度失控；设置页提供服务器状态、版本、路径和测试按钮。

后续再按语言提供可选 sidecar。随包分发时必须锁定版本、校验 checksum/签名，并随应用附带对应 NOTICE。JDT LS、rust-analyzer、clangd 首次索引和内存占用较高，应按工作区按需启动并复用单进程。

## 7. 回滚与降级

- LSP 功能按工作区/语言可关闭。
- 初始化失败、服务器未安装、崩溃或超时自动回退正则 Provider。
- 不改变现有文件保存、工作区监听和恢复库事务。
- 逐阶段提交，P0/P1 任一阶段失败时仍可发布当前轻量导航版本。

## 8. 完成定义

只有同时满足以下条件，才能称为“IDEA 级代码导航基线”完成：

1. 语义引用来自语言服务器，不再依赖全文正则计数。
2. 未打开文件可被定义跳转和引用结果定位。
3. 未保存编辑内容能实时同步，且不会覆盖外部修改。
4. 引用列表、Peek、重命名、诊断和 Outline 有真实 UI 与 E2E 验收。
5. 语言服务器未安装或异常时，编辑器仍可正常编辑并明确降级。
