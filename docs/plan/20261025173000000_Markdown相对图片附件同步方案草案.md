# Markdown 相对图片附件同步 · 接口与流程草案（Tau 0.6.18）

> 状态：草案（待 backend-qa 最终契约对齐）｜范围：Tau 桌面端 + lizi 后端 + 分享页
> 口径：单图 20MB、md 引用图片**默认自动同步**、**计入配额**、格式 png/jpg/jpeg/gif/webp、不做 svg（XSS 风险）

## 1. 目标与不做的部分

- 目标：Tau 同步 md 时把文中引用的**相对路径本地图片**一并上传；分享页能展示这些图片；其他设备拉取文档时把缺失图片下载回本地。
- 不做：图片编辑/裁剪、CDN 转码、断点续传、svg/avif、跨文档图片引用计数回收（第一版按文档维度删除即可）。

## 2. 数据模型

```sql
CREATE TABLE user_document_asset (
  id            BIGINT PRIMARY KEY,
  document_id   BIGINT NOT NULL,            -- user_document.id
  user_id       BIGINT NOT NULL,
  rel_path      VARCHAR(512) NOT NULL,      -- 文档内相对路径，如 images/a.png
  file_name     VARCHAR(255) NOT NULL,
  mime          VARCHAR(64)  NOT NULL,
  size          BIGINT       NOT NULL,
  content_hash  VARCHAR(80)  NOT NULL,      -- sha256:<hex>
  storage_key   VARCHAR(512) NOT NULL,      -- 内容寻址 key（见 §4）
  created_at    DATETIME     NOT NULL,
  updated_at    DATETIME     NOT NULL,
  UNIQUE KEY uk_doc_relpath (document_id, rel_path),
  KEY idx_doc (document_id),
  KEY idx_hash (content_hash)
);
```

## 3. 接口（Tau 端按此实现，最终以后端为准）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/miniProgram/cloud/docs/{fileId}/assets` | 上传单张：`relPath`、`fileName`、`mime`、`contentBase64`（或 multipart）；返回 `{assetId, relPath, fileName, mime, size, contentHash}` |
| GET | `/miniProgram/cloud/docs/{fileId}/assets` | 列表：`[{assetId, relPath, fileName, mime, size, contentHash, updatedAt}]` |
| GET | `/miniProgram/cloud/docs/{fileId}/assets/{assetId}` | 取二进制（鉴权：文档 owner） |
| GET | `/blog/share/{token}/assets/{assetId}` | 分享页取图（公开 + token 校验） |

share 响应新增：

```json
{ "assets": [{ "relPath": "images/a.png", "assetId": 123, "url": "/lizi/blog/share/{token}/assets/123" }] }
```

**服务端校验**（返回 400/413，沿用现有错误码风格）：

1. `relPath` 走与云文档相同的路径校验（拒绝 `..`、绝对路径、盘符、控制字符、超长）；只允许**相对文档所在目录**的路径。
2. 扩展名白名单：`png/jpg/jpeg/gif/webp`；`mime` 必须与扩展名一致。
3. 单图 ≤ 20MB（`413`），总量走配额（`413 QUOTA_EXCEEDED`）。
4. `contentHash` 由服务端按字节重算校验（客户端传的仅用于比对，不一致以服务端为准）。
5. 图片头嗅探（magic bytes）与扩展名/MIME 三者一致，防伪装上传。

## 4. 存储 key 与去重

- `storageKey = assets/{userId}/{docId}/{contentHash前2位}/{contentHash}.{ext}`（**内容寻址**）。
- 同一文档内：`(document_id, rel_path)` 唯一；重新上传同 `relPath` 但 hash 不同 → 覆盖该行（旧 storage 文件可异步清理）。
- 同 hash 图片：存储层天然去重（同 key 只写一次）；不同文档引用同一 key 时按**引用计数**或延迟 GC（第一版建议：只做 storage 写入幂等 + 删除文档时尽力清理，不做跨文档引用计数）。
- 上传幂等：同 `(docId, relPath, contentHash)` 直接返回已有 asset（不重复计费、不重复写盘）。

## 5. 配额计入

- 首次写入某 `storageKey` 时把 `size` 计入 `usedBytes`；同 key 重复引用不重复计。
- 覆盖更新：`usedBytes += newSize - oldSize`（负数回退）。
- 删除文档：删除其 assets 行 + 该文档独占的 storage 文件，`usedBytes -= 被清理的文件 size`。
- 配额校验与文档保存在**同一事务**，沿用现有「用户级行锁」串行化（见 task-1 A 项）。

## 6. Tau 端同步流程（只传变更）

1. 解析 md：`![](...)` 与 `<img src="...">`；**只处理相对路径**（跳过 `http(s)`/`data:`/以 `/` 开头的绝对路径）；处理带空格、`url` 编码（`%20` 等）、嵌套目录（`../` 需归一化到 workspace 根内，越界则跳过并提示）。
2. 本地解析到实际文件（相对**文档所在目录**），校验扩展名白名单 + ≤20MB，不合规**跳过并汇总**，不阻断正文同步。
3. 取 assets 列表 → 按 `relPath + contentHash` 比对，**只上传新增/变更**；并发上限 3；UI 显示「已传 x/y，失败 y 张」。
4. 单图失败不阻断主文档同步；结束后汇总「x 张图片同步失败」，提供重试入口。
5. 设置项「同步文档内图片」默认**开**；关闭时只同步正文并提示存在未同步图片。

## 7. 其他设备拉取（云端 → 本地）

1. 拉文档详情 → 拉 assets 列表。
2. 对每个 `relPath` 计算本地绝对路径（复用 `cloud_doc_open_target` 的路径校验，禁止越出 workspace）。
3. 已存在且 hash 相同 → 跳过；存在但不同 → **跳过并提示**（不覆盖用户文件）；缺失 → 下载写入（父目录自动创建 + 原子写）。
4. 汇总：写入 N 张、跳过 M 张（原因分类）、失败 K 张。

## 8. 分享页渲染

- md 渲染时相对图片改写为 `{shareBaseUrl}/blog/share/{token}/assets/{assetId}`；找不到 asset 的引用 → 渲染「图片未同步」占位块，页脚提示本次分享缺少 N 张图片。
- `Cache-Control: public, max-age=31536000, immutable`（内容寻址可长缓存）；禁止目录遍历，token 失效即 404。
- 分享前 Tau 端校验：本地引用图片与云端 assets 不一致 → 提示「有 N 张图片未同步，是否继续分享」（默认建议先同步再分享）。
- 非 md 文件（code/text/image/pdf/office）沿用 share 响应的 `fileKind/fileExt/fileName` 渲染分流，图片类仍走二进制通道。

## 9. 需要确认的开放问题

1. share 响应里的 `url` 是否含站点前缀（`/lizi/...`）——Tau 端只需透传，分享页拼接时以 `shareBaseUrl` 为准。
2. 同图跨文档是否共享存储（影响配额与删除语义）；建议第一版按文档独占，换实现简单。
3. 20MB 上限是否含 base64 膨胀（建议按解码后字节计）。
4. assets 是否进版本历史（建议不进，只跟随文档当前版本）。
