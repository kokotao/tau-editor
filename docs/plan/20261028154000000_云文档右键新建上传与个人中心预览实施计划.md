## 二、需求评审（必须先对齐的点）

### 2.1 现状事实（评审依据）

1. **云端文档树不是文件系统**：树的两种形态——① 按云端路径 `tau/<workspace>/<相对路径>` 分段（`buildCloudDocTree`）；② 按**分类**分组（`buildCloudDocTreeByCategory`，资源管理器/浏览弹窗实际用的是这种）。分类是独立实体（`cat:<id>`），文件靠 `categoryId` 或分类自由文本 `category` 归位；另有 `group:uncategorized`（未分类）和 `custom:<名称>`（来自文档分类文本、无真实分类行）两种聚合节点。
2. **云文档「新建」= 保存空内容**：后端没有独立的新建接口，`POST /miniProgram/cloud/docs`（`cloud_docs_save`）在 `path` 不存在时创建、存在时按 `baseVersion` 更新。因此 R1 用「保存空正文」实现创建。
3. **二进制文档受单独通道与白名单约束**：pdf/doc/docx/xls/xlsx/ppt/pptx 走 `cloud_docs_binary_upload`（≤50MB、拒宏格式），且请求体只有 `category`（自由文本）**没有 categoryId**；文本类走 `cloud_docs_save`（≤12MB，Rust 侧 `cloud_read_sync_source` 限流）。
4. **打开链路已就绪**：`materializeCloudDocForEdit`（云 → 临时工作区落盘）+ `App.vue#handleCloudDocEditOpen`（打开标签并绑定 `cloudFileId/cloudVersion/cloudContentHash`）已经能打开任意云端文本文档，R1 直接复用，不需要新开链路。
5. **个人中心云文档只有分享跳转**：`cloudDoc/index.vue` 目前只有「打开分享页 / 复制链接 / 到 Tau 打开 / 删除」；后端已具备 `GET /blog/pages/cloud/{docId}`（owner 详情含正文）、`GET /miniProgram/cloud/docs/{fileId}/preview.pdf`（owner，office 由后端转 PDF）、`/{fileId}/download`，R4 **不需要改后端**。

### 2.2 澄清与决策（关键分歧点）

| # | 待澄清 | 决策 | 理由 |
| --- | --- | --- | --- |
| D1 | R1「创建文件」创建的是什么文件？ | 创建**云端文本文档**（默认 `.md`，可写 `.txt/.json/.yaml` 等文本扩展名），创建后立即落到本地临时工作区并在编辑器打开 | 与现有「打开云文档」链路完全一致；用户拿到的是可编辑、可同步的文档，而不是一个空占位 |
| D2 | 新文档的云端路径怎么定？ | `tau/<当前工作区名>/<文件名>`；没有打开工作区时退回 `tau/<分类名>/<文件名>`，都没有则 `tau/未分类/<文件名>` | 路径是文档身份（保存/分享/去重都依赖它）；沿用现有 `tau/<workspace>/...` 约定，避免出现野生前缀 |
| D3 | R1 菜单对哪些节点可用？ | 仅对 `cat:<id>`（真实分类）与 `group:uncategorized`（未分类）可用；`custom:<名称>` 聚合节点禁用并给提示 | `custom:*` 没有分类主键，无法写入 `categoryId`；凭空建分类会污染用户数据 |
| D4 | R2 上传哪些类型？ | 文本类（走云文档保存）+ pdf/office（走二进制上传）；图片、可执行文件、超限文件**跳过并逐条给出原因** | 云端文档模型只支持这两类；图片在本项目里是「文档附件」，不是独立文档 |
| D5 | R2 上传后的归属？ | 落在右键的那个分类下：`categoryId` + `category`（二进制只有 `category` 自由文本）。文件名即路径末段（工作区内保留相对目录结构） | 用户的心智是「往这个分类里丢文件」；保留相对目录能避免同名覆盖 |
| D6 | R2/R3 是否需要并发？ | 串行队列（1 路），批量上限 100 个文件（R2）/ 500 个文件（R3），超限先提示再截断 | 云端一次保存就会产生一个版本，并发只会把配额和冲突面放大；串行还能给出稳定的进度与逐条失败原因 |
| D7 | R3「上传该文件夹」的云端结构？ | 以**文件夹名**为分类（同名分类存在则复用，不存在则新建），把该文件夹下所有可上传文件都同步进该分类；文件路径仍按 `tau/<workspace>/<相对路径>` 生成 | 云端没有"目录"实体，能表达"一组文件"的只有分类；这样右键一次即可在云文档树里看到一个新分类目录 |
| D8 | R3 跳过哪些内容？ | 跳过：`node_modules/.git/dist/build/target/.idea/.vscode/__pycache__/.next/coverage` 等构建与依赖目录、隐藏文件（`.` 开头）、单文件 >50MB 的二进制与 >12MB 的文本、非白名单扩展名 | 防止一次误操作把整个 `node_modules` 推到云端；跳过清单在弹窗里明确列出 |
| D9 | R4「在线预览」要做到什么程度？ | markdown / 代码 / 纯文本 / 图片 / PDF / Office（后端转 PDF）全部可预览；未知类型降级为文件卡片；**不提供下载按钮**（owner 自己的文件另有入口） | 与公开分享页的预览能力对齐，代码与样式尽量复用，避免两套渲染逻辑漂移 |
| D10 | R4 的 markdown 图片？ | 首版**不替换**文档内相对图片（owner 侧附件地址需要鉴权，分享页那套 `?ticket=` 机制不适用），按分享页的「图片未同步」占位展示，并在弹窗底部提示 | 附件鉴权要新增接口，超出本次前端需求范围；显式告知优于静默裂图 |

### 2.3 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| R1 创建的路径与已有文档同名 | 后端 409/覆盖 | 创建前用 `findCloudDocByPath` 预检，命中则提示「同名文档已存在，请改名」，不发起保存 |
| R2/R3 大批量上传触发配额/限流 | 中途失败、用户不知情 | 串行 + 进度弹窗逐条状态 + 结束时汇总「成功 N / 跳过 M / 失败 K（含原因）」；`quota`/`unauthorized` 立即中止队列并提示 |
| R3 误传大目录 | 配额被瞬间打满 | 文件数/深度双上限、跳过目录清单、开始前弹窗显示「将上传 N 个文件」并要求确认 |
| R2/R3 覆盖云端已有内容 | 用户数据被悄悄改写 | 复用 `syncDocumentByPath` 的三方决策：内容相同→跳过；云端有差异→记为「已存在，未覆盖」并提示（**默认不覆盖**） |
| R4 preview.pdf 转换失败 | 白屏 | 422 → 「该文件暂时无法预览（可能仍在转换中）」+ 重试；objectURL 严格释放 |
| 云文档树刷新与弹窗状态不同步 | 用户以为没上传成功 | 上传结束统一 `emit('changed')` + `cloudTreeRefreshToken += 1`，让两处树都重拉 |

## 三、技术方案

### 3.1 R1：分类右键「新建文件」

**交互**：右键分类 → 「新建文件」→ 复用现有 `__prompt` 内联卡片（新增 `mode: 'create-file'`），默认值 `未命名.md`，Enter 提交。

**数据流**

```
CloudDocTree#menuNewFile
  → prompt(mode=create-file, parentId=cat:<id>, categoryName)
  → submitPrompt
      → buildNewCloudDocPath(workspaceName | categoryName | '未分类', fileName)   // 纯函数，可单测
      → findCloudDocByPath(cloudPath)   // 同名预检
      → saveCloudDoc({ path, title: fileName, content: '', baseVersion: null, category, categoryId })
      → emit('changed')                 // 树重拉
      → emit('edit-cloud-doc', 合成节点) // App.vue 走既有落位 + 打开 + 绑定
```

**服务**：新增 `services/cloudDocCreateService.ts`
- `sanitizeNewDocName(raw): { ok: true; name: string } | { ok: false; reason: string }`（禁 `/ \ : * ? " < > |`、`..`、空串、超长，自动补 `.md` 当无扩展名）
- `buildNewCloudDocPath(workspaceName, fileName): string` → `tau/<ws>/<name>`
- `createCloudDocFile(input): CloudOutcome<{ fileId; version; contentHash; cloudPath }>`

**注意**：新建后不要本地写盘（`materializeCloudDocForEdit` 会按云端内容落位），避免出现两份不同步的本地副本。

### 3.2 R2：分类右键「批量上传」

**交互**：右键分类 → 「上传文件…」→ `open({ multiple: true })` 多选 → 新弹窗 `CloudDocUploadDialog.vue`（列表 + 每项状态 + 进度条 + 取消/关闭），结束后汇总。

**服务**：新增 `services/cloudDocBatchUploadService.ts`
- `planBatchUpload(localPaths, target): UploadPlanItem[]`（纯函数：区分 `text | binary | skipped`，给出 reason）
- `runBatchUpload(plan, target, callbacks)`（串行执行 + 进度回调 + 中止条件 `quota|unauthorized`）
  - text：`syncDocumentByPath({ filePath, categoryId, category })`；`status === 'conflict'` 视为「已存在，未覆盖」
  - binary：`uploadBinaryDocument({ cloudPath, localPath, title, category })`
- 上限 `BATCH_UPLOAD_MAX_FILES = 100`

**i18n**：面板文案新增 `menuNewFile/menuUploadFiles/uploadDialogTitle/uploadSummary/...`（见 4.1）。

### 3.3 R3：工作区文件夹右键「上传该文件夹」

**交互**：`FileTree.vue` 文件夹行右键 → 「上传该文件夹到云端」→ `App.vue` 打开 `CloudFolderUploadDialog.vue`（确认 + 进度 + 汇总）。菜单项仅在文件夹行出现，且未登录时引导登录。

**服务**：新增 `services/cloudFolderUploadService.ts`
- `SKIP_DIR_NAMES` / `SKIP_FILE_EXTENSIONS` 常量与 `shouldSkip(name, isDir)`（纯函数）
- `collectFolderFiles(rootPath, options): { files: FolderFile[]; skipped: SkipEntry[]; truncated: boolean }`
  - 用 `fileCommands.listFiles(dir)` 递归；深度上限 8、文件数上限 500、单文件大小上限（文本 12MB / 二进制 50MB）
- `runFolderUpload({ rootPath, files }, callbacks)`：先 `createCategory(folderName)`（409 走「复用同名分类」→ 查 `fetchManagedCategories`），再逐文件按 3.2 的规则上传
- 参考实现：`syncBinaryDocument`（`App.vue`）与 `syncDocumentByPath`（`cloudSyncService.ts`）

**宿主接线**：`App.vue` 新增 `@upload-folder="handleFileTreeUploadFolder"`，上传完成后 `cloudTreeRefreshToken += 1`。

### 3.4 R4：栗子个人中心在线预览

**契约**（已存在，不改后端）：`GET /blog/pages/cloud/{docId}`、`GET /miniProgram/cloud/docs/{fileId}/preview.pdf`、`GET /miniProgram/cloud/docs/{fileId}/download`。

**结构**：
- `api/lizi/mySpace.ts`：`getCloudDocDetail` / `downloadCloudDocPreviewPdf` / `downloadCloudDocBinary`
- `views/system/cloudDoc/components/CloudDocPreviewDialog.vue`：按 kind 分支渲染，复用 `utils/share-render.ts` 与分享页 `PdfPreview.vue`
- `views/system/cloudDoc/index.vue`：操作列「预览」+ 双击行预览

**类型判定**：列表项没有 `fileKind/fileExt`，沿用现有 `resolveFileExt({ fileName: item.fileName || item.path || item.title })` + `normalizeFileKind`。
