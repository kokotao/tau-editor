## 1. 结果

搜索命令从“同步一次性返回”升级为“带 searchId 的可取消会话”，替换从“直接覆盖写”升级为“先预览不可重叠计划、再按选中项逐文件提交、可撤销”。全部质量门禁通过。

## 2. 交付内容

### 后端

| 能力 | 实现 |
|---|---|
| 可取消搜索 | `search_workspace` 新增 `searchId`；`services/search_session.rs` 提供 `SearchSessionRegistry`（begin/cancel/finish/purge_expired），搜索过程中按目录项、文件、行三处检查取消标记 |
| 部分结果返回 | `SearchResponse.cancelled` 为 true 时返回已扫描到的部分结果，前端提示“已取消，以下为部分结果” |
| 失效会话 | 重复 searchId 返回 `SEARCH_IN_PROGRESS`；已结束或未知 searchId 返回 `SEARCH_EXPIRED`；会话 300 秒超时自动清理 |
| 取消命令 | 新增 `cancel_search` / `SearchCancelResponse` |
| 替换预览 | 新增 `preview_workspace_replace`：只读扫描工作区，跳过 `.git`、`node_modules`、`target`、`dist` 与 2 MiB 以上文件，命中按行收集、跳过零长度匹配，生成 `matchId = 相对路径#序号` 与替换前后整行对比 |
| 计划冻结 | `services/replace_preview.rs` 冻结每个文件的 revision 与命中数量；同一 previewId 只能提交一次（提交即消费） |
| 按计划提交 | `apply_workspace_replace_preview`：逐文件复核 revision，外部改动返回 `conflict` 且不写盘；逐项返回 `applied`、`skipped`、`conflict`、`failed` |
| 撤销 | `undo_workspace_replace`：保留替换前内容与写入后 revision，撤销时逐文件 revision 校验回写；单文件 1 MiB、单次 8 MiB 上限 |
| 保守边界 | 选中项按行内从后往前替换，保留 CRLF 与末行无换行；未知 matchId 返回 `MATCH_ID_INVALID` 且不写盘 |

### 前端

| 能力 | 实现 |
|---|---|
| 搜索取消 | `searchCommands.workspace(workspaceId, searchId, query, options)`、`searchCommands.cancel(searchId)`；App.vue 维护 searchId 序列，新搜索前先取消上一轮，过期结果按 searchId 丢弃 |
| 替换入口 | `WorkspaceSearchPanel` 新增替换输入与“预览替换”，支持 Esc/Enter 与取消按钮 |
| 预览对话框 | 新增 `ReplacePreviewDialog.vue`：默认全选、按文件全选/全不选、逐项前后对比、逐文件结果状态、撤销按钮 |
| 落盘后同步 | 替换/撤销后，干净的已打开标签从磁盘重载，脏标签标记外部冲突并提示，文件树刷新 |

## 4. 风险与回滚

- 预览提交是一次性消费：apply 失败或返回冲突后必须重新预览，这是刻意设计，避免旧计划被重复执行。
- 多行正则（如跨行 `[\s\S]`）不在预览范围内，与既有搜索按行匹配的语义一致。
- 撤销仅覆盖经预览计划写入的文件，且受 1 MiB/文件、8 MiB/次上限约束；超限文件标记 `undoable: false`。
- 旧命令 `apply_workspace_replace` 仍保留在后端用于兼容，前端已不再调用。
- 回滚：删除 `services/replace_preview.rs`、`services/search_session.rs` 与对应命令注册，恢复 `commands/search.rs` 旧实现即可；数据层无迁移。
