> 结论：W3 功能闭环完成，前后端验证通过；E2E 用例留待 W7 补齐

## 1. 结果摘要

后端从零接入 `notify` 递归工作区监听并推送 `workspace:file-changed` 事件；前端新增 watcher 服务、冲突 store、冲突弹窗并接入 `App.vue`。dirty 文件在外部变更时只标记冲突不覆盖内存内容，clean 文件自动重载，重命名跟随已打开标签，监听不可用时自动退回原有 1.5 秒轮询。

过滤与归一化规则：

- 忽略目录：`.git`、`node_modules`、`target`、`dist`、`.next`、`.idea`。
- 忽略文件：`.DS_Store`、`Thumbs.db`、`desktop.ini`，以及 `*.tmp`、`*.swp`、`*~` 等临时文件。
- 原子替换（临时文件改名到目标文件）归一为 `modified`，用户显式重命名保留为 `renamed` 并带 `oldPath`。
- 忽略 Access 类事件，避免读取即触发推送。

### Agent-FE-Conflict（前端）

| 文件 | 说明 |
|---|---|
| `frontend/src/services/workspaceWatcherService.ts` | 订阅事件、启动/停止监听、路径归一化（Windows 盘符小写、分隔符统一）、载荷校验；启动失败返回 `false` 供调用方退化；含并发保护，避免启动中途 stop 留下悬挂订阅 |
| `frontend/src/stores/fileConflicts.ts` | `flag/find/resolve/retainOnly/clear`，按归一化路径索引，保存磁盘时间、磁盘大小和本地基线 |
| `frontend/src/components/editor/ExternalChangeDialog.vue` | 展示变更类型、本地基线、磁盘时间；动作为重新加载 / 保留当前内容 / 另存为 |
| `frontend/src/lib/tauri.ts` | 新增 watcher DTO、`watcherCommands`、`listenWorkspaceFileChanges` 事件出口（延迟加载 Tauri 事件模块） |
| `frontend/src/components/editor/ContextRail.vue` | 新增冲突详情文案与 `context-conflict-details` 按钮 |
| `frontend/src/App.vue` | 订阅 watcher 事件、批量处理变更、冲突动作、轮询退化、标签关闭清理冲突 |

`App.vue` 行为规则：

- 变更路径在当前工作区内时刷新文件树。
- `renamed` 且 oldPath 命中已打开标签时跟随新路径，不重读内容。
- `removed` 与 dirty 标签：写入冲突记录并提示一次，不覆盖内存内容。
- clean 标签：自动重载并清除冲突。
- 轮询退化路径同样写入冲突记录，保证「详情」入口在无原生监听时仍可用。

## 4. 风险与回滚

| 风险 | 等级 | 应对 | 回滚 |
|---|---|---|---|
| 监听事件触发自身写入循环 | 中 | 过滤临时文件与构建目录，事件去抖 250 ms，原子替换归一为 modified | 前端 `startExternalFileWatch` 返回 false 时自动退回 1.5 秒轮询 |
| 大工作区事件量过大 | 中 | 单批上限 200，后台线程处理，前端按批刷新文件树一次 | 关闭监听命令，退回轮询 |
| 冲突提示重复干扰 | 低 | `flag` 返回是否首次记录，仅首次弹通知 | 调整 `fileConflicts` 提示策略 |
| 三方 Diff 未实现 | 中 | 弹窗展示基线时间与磁盘时间，动作明确；完整 Diff 归入后续版本 | 保留现有重载/保留/另存为路径 |
