## 3. 接口契约（已实现）

统一返回体 `Result<T>`（`{success,code,message,data}`）；**业务错误码走 HTTP 200 + body.code**（沿用项目 `GenericExceptionHandler` 现状）。

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| GET | `/miniProgram/cloud/docs/me` | — | `{userId,usedBytes,quotaBytes,fileCount,maxVersionPerFile}` |
| GET | `/miniProgram/cloud/docs` | `pathPrefix`、`keyword`、`page=1`、`size=50` | `{records:[...],total,page,size}` |
| POST | `/miniProgram/cloud/docs` | `{path,title?,content\|contentBase64?,contentHash?,baseVersion?,category?,categoryId?,tags?,visibility?}` + `X-Device-Id?` | `{fileId,version,contentHash,size,updatedAt}` |
| GET | `/miniProgram/cloud/docs/{fileId}` | — | 列表项字段 + `content` + `createdAt` |
| GET | `/miniProgram/cloud/docs/{fileId}/versions` | — | `[{versionId,version,contentHash,size,remark,createdAt}]` |
| POST | `/miniProgram/cloud/docs/{fileId}/versions/{versionId}/restore` | `X-Device-Id?` | 同保存结果 |
| DELETE | `/miniProgram/cloud/docs/{fileId}` | `X-Device-Id?` | `Result<Void>` |

错误码约定：`400` 参数/路径/内容非法、`401` 未登录、`404` 文档不存在或非 owner（不暴露存在性）、`409` 版本冲突、`413` 云端空间不足。

鉴权：`/miniProgram/cloud/docs/**` **不在** `SecurityConfig.PUBLIC_PATHS`，由 `anyRequest().authenticated()` 兜底；Controller 内再用 `SystemTokenUtil.geUserInfoFromToken()` 取 `SysUser.id` 作为 owner。

## 4. 关键设计决策

1. **版本并发**：`SELECT ... FOR UPDATE` 行锁（`lockByPath`/`lockById`）串行化同一文档的版本分配；`baseVersion` 乐观校验兜底冲突（409）。首次创建无行可锁，由 `uk_user_path` 唯一键保证，重复键捕获后转 409。
2. **版本裁剪**：每文档保留最近 `maxVersionPerFile`（默认 30）个版本**行**，只删行不删文件（方案 §6 V1 不做内容清理，V2 后台脚本）。
3. **内联副本**：≤1MB 且为文本时，正文冗余存 `content` 列，便于在线编辑/后续发布；文件始终落盘，`content` 为空时回读存储。
4. **软删除与唯一键**：删除时 `is_deleted=1`、`status=DELETED`，并把 `path` 改写为 `原路径 + " #deleted:{id}"`，既保留审计又允许同路径重建（避免 `uk_user_path` 冲突）。
5. **配额**：`usedBytes + newSize - oldSize > quotaBytes → 413`，**新建/覆盖/恢复三条写路径都校验**，且校验在落盘前，失败不产生文件与脏行。
6. **元数据保留**：覆盖保存时 `category/categoryId/tags/visibility` 若请求为空视为「不修改」，避免客户端只推正文把 PUBLIC 打回 PRIVATE。
7. **存储 SPI**：`DocumentStorage` 抽象；`storage_key` 不可预测（UUID + 白名单化扩展名），私有内容**不落** `/file/**` 公开静态映射，下载统一走带鉴权的接口流。
8. **失败审计**：主流程失败时用 `REQUIRES_NEW` 独立事务写 `user_document_sync_log`（FAIL），保证主事务回滚不影响日志落库；日志写入自身失败只告警。
9. **安全**：路径禁止 `..`/绝对路径/控制字符/Windows 非法字符，段数与长度受限；`read/delete` 做 canonicalPath 穿越防护；日志不记 token 与正文。
