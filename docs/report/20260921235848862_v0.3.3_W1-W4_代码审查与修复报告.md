## 2. 问题清单

### P1-1 大文件保存期间继续输入会被误标为已保存（已修复）

- 位置：`frontend/src/services/tabService.ts` `saveActiveTab`。
- 现象：大文件事务写入可能持续数秒，写入完成后无条件 `isDirty: false` + `markAsSaved()`；此期间用户新输入的内容并未写入磁盘，却会被标记为已保存，存在静默丢失风险。
- 修复：保存前记录 `contentSnapshot`，保存后比较标签当前内容；内容已变化时保持 `isDirty: true` 且不调用 `markAsSaved()`，同时仍写入新的 `fileRevision` 基线。
- 验证：`tests/unit/services/tabService.test.ts` 新增「保存期间继续输入时保持脏标记并写入新基线」。

### P1-2 revision 基线可在保存前被自证，静默覆盖外部修改（已修复）

- 位置：`frontend/src/services/tabService.ts` `commitLargeFileRevision`。
- 现象：原实现保存前调用 `getFileRevision` 取当前磁盘 revision 作为 `expectedRevision`。若监听漏报外部修改，基线读取到的已是外部修改后的版本，事务会正常提交并覆盖它。
- 修复：基线改为**打开/加载文件时捕获**（`WorkspaceService.captureFileRevision`）并存入 `Tab.fileRevision`；保存只使用该基线，缺失时抛 `REVISION_BASELINE_MISSING` 并拒绝覆盖。磁盘重载与「保留当前内容」两个显式动作会刷新基线。
- 验证：`tabService.test.ts` 断言保存不再调用 `getFileRevision`、基线缺失时阻止保存；`workspaceServiceLargeFile.test.ts` 断言打开时捕获基线。

### P2-3 大文件外部变更重载会整块读入内存（已修复）

- 位置：`frontend/src/App.vue` `reloadTabContentFromDisk`。
- 现象：clean 标签被外部修改后自动重载走 `fileSystemStore.readFileContent`，Rust `read_file` 无大小限制，数百 MB 文件会一次性进入内存并冻结界面。
- 修复：重载逻辑下沉为 `WorkspaceService.reloadFileFromDisk`；大文件关闭标签后按分段流程重新打开（复用首屏分块加载并重新捕获基线），普通文件保持整块读取 + 刷新基线。返回值告知调用方是否需要同步编辑器。
- 验证：`workspaceServiceLargeFile.test.ts` 新增「大文件重载走分段重新打开」与「普通文件重载整块读取并刷新基线」。

### P2-4 依赖双副本导致 `vi.mock` 失效（已修复）

- 位置：`vitest.config.ts`。
- 现象：根 `node_modules` 与 `frontend/node_modules` 各有一份 `@tauri-apps/plugin-dialog`（同版本 2.6.0 但物理路径不同），`frontend/src` 下单测对 dialog 的 mock 不生效，测试会调用真实 `save()` 并抛 `Cannot read properties of undefined (reading 'invoke')`。
- 修复：vitest `resolve.alias` 将 `@tauri-apps/plugin-dialog` 统一指向 frontend 副本。
- 验证：`tabService.test.ts` 的另存为用例现在能正确注入目标路径。

## 3. 观察项（未修复，风险可接受）

| 编号 | 位置 | 说明 | 结论 |
|---|---|---|---|
| O-1 | `services/file_transaction.rs` | 事务注册表没有并发事务数上限，仅受分片/总量/超时约束 | 本地单用户应用，前端一次只开一个事务；后续可加并发上限 |

## 4. 审查确认项

- Rust 新增代码生产路径无 `unwrap()`/`expect()`，`expect` 仅出现在 `#[cfg(test)]`。
- 恢复库草稿文件名使用 `sha256(path|id)`，不存在路径穿越；写入走临时文件 + `sync_all` + 原子替换 + 父目录同步。
- 事务提交前再次校验 revision，冲突时删除临时文件且不改动原文件；`ensure_expected_revision` 拒绝软链接与非普通文件。
- 监听过滤忽略 `*.tmp`，因此事务临时文件不会触发自身变更事件。
- 新增命令已全部注册到 `lib.rs` 的 `generate_handler!`。
