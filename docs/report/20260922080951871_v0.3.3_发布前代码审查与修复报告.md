## 2. 已确认无问题的关键点

- **W7 flush 时序**：`EditorCore.vue` 在 `onDidChangeModelContent` 里只记录 `pendingContentModel` + `pendingContentModelId`（由 `WeakMap<ITextModel, string>` 反查，避免用 `activeModelId` 兜底串号），真正提交统一走 `flushPendingContent()`；`activateModel()` 在切模型前调用它，`editorStore.setContent` 只在「当前编辑器模型 === 待提交模型」时执行。
- **回写路由**：`App.vue` `handleContentChange(content, modelId)` → `tabService.updateTabContent(modelId, content)`，非活动标签只更新 tabs store、不污染 editor store，`isActiveTab` 分支正确短路。
- **脏标记与保存竞态**：`TabService.saveActiveTab` 用 `contentSnapshot` 做保存后复核，保存期间继续输入不会被误标为已保存；被 `FILE_CONFLICT` / `REVISION_BASELINE_MISSING` 拦截时直接返回并给出可操作提示，不写盘。
- **大文件 revision 基线**：`expectedRevision` 取自打开时捕获的 `tab.fileRevision`，保存前不重新采样，避免监听漏报时把外部改动当作合法基线。
- **Windows 抑制标志覆盖面**：`settings.rs`、`file_association.rs`、`git.rs` 三处均通过 `creation_flags(CREATE_NO_WINDOW)` 启动子进程，`rg` 复核无遗漏的裸 `Command::new` 调用点。
- **CI YAML 合法性**：`test.yml` 经解析校验，jobs 为 `frontend-check` / `frontend-unit` / `rust-check-and-test` / `frontend-e2e`；E2E job 复用了根 `playwright.config.ts` 的 `webServer`（`frontend` 目录 `pnpm dev`，端口 5173），与本地执行路径一致。
- **配置文件**：`tauri.conf.json` 通过 `python3 -m json.tool` 校验。
