## 3. 关键设计决策

1. **token 只在 Rust**：桌面端所有 HTTP 与 JWT 存于 Rust（keyring + 内存会话），前端 JS 拿不到 token；Web 版降级为模块内内存变量，**全流程不写 localStorage/sessionStorage**（单测断言 `storage.size === 0`）。
2. **登录方式**：桌面端只用账号密码（`POST /lizi/user/login`，form-urlencoded），微信 code 登录依赖小程序 `wx.login()` 无法在桌面复用；登录失败（code 101/201/300）保留服务端原文案展示，不误报「登录过期」。
3. **错误码按 code 而非 HTTP status**：服务端业务错误是 HTTP 200 + `body.code`（409 冲突 / 413 配额），Rust `parse_result` 统一映射为 `CONFLICT/QUOTA_EXCEEDED/UNAUTHORIZED/SERVER_ERROR`，TS 只读 `TauriError.code`。
4. **sha256 由 Rust 算**：现有 `get_file_revision(include_hash)` 不可用（`HASH_UNSUPPORTED`），新增 `cloud_read_sync_source` 返回文本内容 + `sha256:<hex>` + size + mtime。
5. **同步白名单**：复用 `workspaceService` 的 12MB 阈值与二进制预览扩展名集合（pdf/doc/docx/xls/xlsx/db/sqlite/sqlite3 等），图片与二进制不同步；Rust 侧再兜底判非 UTF-8 → `BINARY_FILE`。
6. **冲突不自动覆盖**：三方决策（本地 hash / 云端 hash / 上次同步基线）判出 `conflict` 时只登记 `fileConflicts`，由用户决定覆盖或拉取；P2 再接三路 diff 面板。
7. **云路径规则**：`tau/{workspaceName}/{相对路径}`，反斜杠归一、去空段/`.`/`..`、整串截断 512；云端唯一键 `(user_id, path)` 与 P0 一致。
8. **UI 落点**：设置页新增分类 + 命令面板，零穿透 `Toolbar`/`StatusBar` 的 props 链路。

## 5. 已知限制（P1 接受，P2/P8 再处理）

1. **跨会话首同步可能判冲突**：`docMap` 已持久化「上次同步的 fileId/version/hash」，但当前三方决策的基线取 `tab.cloudContentHash`（标签级，重启后为空）。重启后首次同步若本地与云端都变过会保守判冲突（不会丢数据）。
2. 冲突登记复用 `fileConflicts` 的 `kind: 'modified'`（未新增云冲突类型）；P8 做冲突面板时再扩展。
3. `App.vue` 与 `SettingsPanel.vue` 都会调 `initialize()`（打开设置会再恢复一次会话），当前无幂等短路。
4. 无自动同步（保存后防抖/退出同步属 P2）、无 refresh token 续期（过期需重新登录）、无版本列表/恢复 UI（接口已就绪）、无分类/标签/可见性 UI（P3）。
5. 不同步二进制与非 UTF-8 文件（GBK 文本会被拒），符合方案「V1 文本类为主」。

## 6. 手工验收步骤（P1 闭环）

1. 起 lizi 后端（`port 5180` + `context-path /lizi`，需 MySQL/Redis），执行 P0 的 DDL。
2. `pnpm dev`（Web）：设置 → 云同步 → 服务器地址填 `http://localhost:5180/lizi` → 账号密码登录 → 打开一篇 `.md` → 同步当前文档 → 云端应出现 `user_document` 记录（version=1）；改两行再同步 → version=2。
3. `pnpm tauri:dev`（桌面）：同上；**重启应用后仍是登录态**（keyring 生效）。
4. 冲突验证：用 curl 直接 `POST /miniProgram/cloud/docs` 改云端 → 本地再改一行 → 同步 → 提示冲突、不自动覆盖。
5. 白名单验证：打开 `a.docx` 或 >12MB 文件 → 同步返回「不支持」原因。
