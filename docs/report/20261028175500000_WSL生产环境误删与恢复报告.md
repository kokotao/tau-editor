# WSL 生产环境误删与恢复报告（2026-10-28）

> 事故类型：AI 助手执行部署命令时，内联脚本变量被外层 shell 提前展开为空，`rm -rf "<空>/*"` 实际执行成 `rm -rf /*`，删除了本机 WSL 发行版 `Ubuntu-D`（同时承载 note.lizipro.cn 前端、后端与全部容器）根文件系统的部分目录。
> 影响窗口：2026-10-28 约 17:23 — 17:39（约 16 分钟 502）。
> 记录人：AI 助手 ｜ 复核人：待补

## 一、事故经过

1. 按「上线」指令准备把前端产物同步到 WSL 站点目录（`/opt/1panel/www/sites/lizi/index`），执行了一条内联脚本：
   ```sh
   wsl -d Ubuntu-D -u root -- sh -c 'SITE=/opt/... ; rm -rf "$SITE"/* ; ...'
   ```
2. 该命令经工具层 `bash -c "…"` 传递时，单引号内的 `$SITE` 被**外层 shell 提前展开为空串**，实际执行变为 `rm -rf /*`。
3. 首次删除遍历了 `/etc`、`/home`、`/boot`，并进入 `/mnt/d` 等 Windows 挂载点（部分文件因占用报 I/O error 未删成功）。
4. 随后 WSL 无法启动（`getpwnam(root) failed`），`note.lizipro.cn` 返回 502。
5. 第二次尝试部署时再次触发同类展开问题，但命令在 `rm` 前即被中断，未造成二次破坏（事后核对 `/etc` 仍有 84 项、站点目录完好）。

## 三、恢复步骤（已执行）

1. 立即 `wsl --shutdown` 终止可能的删除进程。
2. 下载 Alpine minirootfs，`wsl --import` 出临时救援发行版 `rescue2`，`wsl --mount --vhd` 挂载 `D:\WSL\Ubuntu-D\ext4.vhdx` 到 `/dev/sdd`。
3. 从官方 `ubuntu-base-24.04.3-base-amd64.tar.gz` 恢复 `/etc`、`/boot` 骨架。
4. 重建关键符号链接：`/bin → usr/bin`、`/lib → usr/lib`、`/lib64 → usr/lib64`（保留 `/sbin → usr/sbin`）。
5. 补 `/etc` 机器相关配置：`hostname`、`hosts`、`wsl.conf`（`systemd=true`、默认用户 albert）、`machine-id`、`fstab`、`sshd_config`、`sudoers.d/90-albert`（NOPASSWD，恢复后建议按需收紧）。
6. 补系统账号：`albert(1000)`、`docker(999)`、`sshd(110/113)`、`landscape`；`albert` 加入 `docker` 组。
7. 修复 `iptables` alternatives（`update-alternatives --set iptables /usr/sbin/iptables-nft`），否则 dockerd 起不来。
8. 启用并启动 `docker`，31 个容器按 restart 策略自动拉起（含 `lizi-learning-management`、`1Panel-mysql-d7H7`、`lizi-frontend-5200`、`1Panel-openresty`）。
9. 恢复 1Panel 面板服务单元（`/etc/systemd/system/1panel.service`）并启动。
10. 生成 SSH 主机密钥、启用 `ssh`（端口 2223）、把本机公钥追加进 `/root/.ssh/authorized_keys`，恢复部署通道。
11. 安装 CA 证书包（`/etc/ssl/certs/ca-certificates.crt`），恢复容器/apt 出网 HTTPS。
12. 备份当前站点后部署 v0.6.27 配套前端（含并行 WIP）：`/mnt/d/lizi-web-backup-20261028-174742.tgz`。
13. 清理救援发行版与临时文件。

## 五、遗留问题与待办（重要）

1. **`/home/albert` 内容丢失**：家目录已重建为空，原 dotfiles/个人文件无法恢复（如曾有重要内容需从其他备份找回）。
2. **`/etc` 为 Ubuntu 24.04.3 base + 手工补丁**：包级配置可能缺失或回到默认，建议逐项核对：
   - 自建 `systemd` 单元（现在仅 `docker`、`ssh`、`1panel` 被显式启用）
   - `/etc/docker/daemon.json`、`/etc/containerd/config.toml`（当前为默认值）
   - `crontab`（root/albert 的定时任务）、`/etc/hosts` 自定义条目、`/etc/environment`
   - SSH 客户端 key、`authorized_keys` 之外的访问控制
   - `/etc/passwd` 中 landscape/sshd 等为手工补建，后续 `apt` 升级到相关包时可能提示冲突，可执行 `dpkg --configure -a` 收口
3. **D 盘部分文件可能被删**：建议对 D 盘做一次全盘核对（`chkdsk /f` 与关键目录抽样），已知丢失 `D:\lizi-web-backup-20261028-1719.tgz`（可由新备份替代）。
4. **建议立即建立备份**：
   ```bash
   # WSL 整体导出（建议停服或低峰执行）
   wsl --export Ubuntu-D D:\WSL\backup\Ubuntu-D-$(date +%Y%m%d).tar
   # 站点目录备份（已有：/mnt/d/lizi-web-backup-20261028-174742.tgz）
   ```
5. **操作规范（避免复发）**：
   - 任何含 `rm -rf` 的脚本先 `set -eu` 并对路径变量做 `[ -n "$VAR" ] || exit 1` 校验；
   - 路径变量优先写进脚本文件由目标系统解释，不在跨 shell 的内联字符串里使用 `$VAR`；
   - 部署脚本内“备份成功”后才允许删除目标目录；
   - 对生产目录的所有写操作先做备份并记录备份路径。
