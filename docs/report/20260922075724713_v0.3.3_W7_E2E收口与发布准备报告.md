## 2. 缺陷修复（P1：标签切换内容串写）

**现象**：`E2E-TAB-002` 在并发执行下稳定复现——第二个标签输入内容后切换标签，内容丢失或出现在其它标签。

**根因**（通过 trace 时间线 + 浏览器内埋点确认）：

1. 编辑器内容变更走 50ms 去抖后再提交，提交时读取的是「当前挂载模型的值」和「当前活动标签」。
2. 若用户在去抖窗口内切换标签，提交发生在切换之后：读到的已是新模型的值，却写入新的活动标签 → 旧标签输入丢失、新标签内容被污染。
3. 之后切回原标签时，`activateModel` 会用标签 store 里的旧内容回写模型，覆盖掉模型内尚未提交的输入。

**修复**：

- `EditorCore.vue`：记录待提交内容所属的**模型对象**与**模型 id**；新增 `flushPendingContent()`，按模型取值并按 id 上报；`activateModel()` 在切换模型前先 flush 一次。
- `tabService.ts`：新增 `updateTabContent(tabId, content)`，按标签 id 回写；仅当目标标签是活动标签时才同步编辑器 store；`updateActiveTabContent` 改为其薄封装。
- `App.vue`：`handleContentChange(content, modelId)` 改为按模型 id 路由回写。

**验证**：并发复跑 `tab-management.spec.ts --repeat-each=3 --workers=3` 连续多轮全绿（修复前同样条件稳定失败）；新增单测锁定两条回归路径（`EditorCore` 切换前 flush、`TabService` 非活动标签回写不污染 store）。

- 风险：内容回写改为按模型 id 路由后，若未来出现同一标签多模型（如预览编辑同源）需保证模型↔标签映射唯一；当前 `getOrCreateModel` 一对一注册，无歧义。
