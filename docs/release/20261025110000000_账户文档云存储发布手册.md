## 2. 部署顺序（不可调换）

1. **备份数据库**（至少 `article`、`role`、`sys_user`）。
2. **执行 DDL（幂等，可重复执行）**：
   ```bash
   docker exec -i 1Panel-mysql-d7H7 mysql -uroot -p --default-character-set=utf8mb4 lizi-learning < sql/20261024174525300_add_user_document_tables.sql
   docker exec -i 1Panel-mysql-d7H7 mysql -uroot -p --default-character-set=utf8mb4 lizi-learning < sql/20261025_add_article_cloud_doc_fields.sql
   docker exec -i 1Panel-mysql-d7H7 mysql -uroot -p --default-character-set=utf8mb4 lizi-learning < sql/20261025_add_tau_author_role.sql
   ```
   > ⚠️ **必须先在库里执行 article 增量列，再启动新 jar**：`Article` 实体已含 `source/publish_channels/cloud_doc_id`，MyBatis-Plus 会把三列写进所有 article 查询，缺列会导致博客/小程序文章接口 `Unknown column` 500。
3. **后端发版**：上传 jar 到 `/usr/local/runtime/` → 重启服务 → 验证：
   - `GET /lizi/v3/api-docs` 200
   - `GET /lizi/miniProgram/cloud/docs/me` 未登录 401
   - 日志无 `Unknown column` / `doesn't exist`
4. **博客前端发版**：`lizi-learning-vue-admin` 常规构建发布（新增路由 `/blog/cloud/:docId`、匿名白名单 `/blog/cloud`）。
5. **给首批 Tau 作者授权**：管理员登录后台调用（或直接 SQL 追加 `roles_id`，不覆盖原值）：
   ```
   POST /lizi/tauAuthor/{userId}/grant
   GET  /lizi/tauAuthor/list
   ```
6. **Tau 客户端打包**：`cd frontend && pnpm tauri build`；Windows 需 NSIS 工具链（首轮安装会联网下载）。默认服务器地址 `https://note.lizipro.cn/lizi`，可在设置页修改。
   > ⚠️ 本机踩坑：默认 Rust 工具链是 `x86_64-pc-windows-gnu`（msys64 mingw），`tauri build` 在链接 cdylib 时报 `export ordinal too large: 82338`（GNU ld 的 65535 导出序号上限），属工具链限制而非代码问题。
   > 解决：改用 MSVC 工具链（本机已有 VS 2022 Community / VS2019 BuildTools 的 C++ 工具）：
   > ```powershell
   > rustup toolchain install stable-x86_64-pc-windows-msvc --profile minimal
   > $env:RUSTUP_TOOLCHAIN='stable-x86_64-pc-windows-msvc'
   > cd frontend; pnpm tauri build
   > ```
   > 已验证：MSVC 下 `tauri build --no-bundle` 成功产出 `frontend/src-tauri/target/release/text-editor.exe`（约 13MB，release 编译约 5m21s）。
   > 完整打包（NSIS 安装包）：`$env:RUSTUP_TOOLCHAIN='stable-x86_64-pc-windows-msvc'; pnpm tauri build --bundles nsis`
   > 产物：`frontend/src-tauri/target/release/bundle/nsis/Tau Editor_0.6.13_x64-setup.exe`
   > 大小 7.5MB，SHA256 `E15358B398709D869238C135E0172B0E68529C32702AA69E3CF9A9D60EBADD52`（2026-10-25 10:47 构建）。
   > 注：首次打包尝试默认 bundle 时会从 GitHub 下载 WiX（MSI 工具链），本机网络中断导致失败（os error 10053）；改用 `--bundles nsis` 后成功（NSIS 工具链已缓存）。

## 3. 环境变量（后端）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CLOUD_DOC_QUOTA_BYTES` | `1073741824`（1GB） | 单用户云端配额 |
| `CLOUD_DOC_MAX_FILE_BYTES` | `209715200`（200MB） | 单文件上限 |
| `CLOUD_DOC_MAX_VERSION_PER_FILE` | `30` | 每文档保留版本数 |
| `CLOUD_DOC_MAX_PATH_LENGTH` / `MAX_TITLE_LENGTH` | `512` / `255` | 路径/标题上限 |

已有部署变量（必须沿用）：`DB_HOST/DB_PORT/DB_NAME/DB_USERNAME/DB_PASSWORD`、`REDIS_HOST/REDIS_PORT/REDIS_PASSWORD`、`SYS_DATA_URL`（`sys_params` 参数，云文档落盘在 `${SYS_DATA_URL}/cloud/...`）、`EXPIRE_TIME`（JWT 过期分钟，缺失会导致登录签名失败）。

## 5. 回滚方案

1. **后端**：回滚 jar 到上一版本即可；本期只新增表与新接口，不影响既有功能。
2. **DDL**：三张新表与 `article` 三列保留（新 jar 回滚后不再读写这些列，无副作用）；如需彻底清理，先确认无云文档数据后再 drop。
3. **博客前端**：回滚 dist；`/blog/cloud` 路由与「我的文章」分段随之消失，公开列表不受影响。
4. **Tau 客户端**：回滚安装包；云端数据保留，旧版本不感知。

## 6. 已知限制与待决策（方案 §12）

1. `article` / `category` 基础表不在仓库 dump 中（本地联调按实体补齐），生产库已有，但发版前需核对生产 `article` 列与实体一致。
2. 配额是否与会员体系联动（普通 1GB / 会员 10GB）——待产品确认。
3. 云端文档是否加密存储、运营可见性——待安全确认。
4. `workspaceName` 作为云路径前缀，跨设备同名工作区会落到同一路径——建议后续改用 workspaceId 或用户可配前缀。
5. V1 不清理历史版本文件（只删版本行），V2 提供后台清理脚本。
6. `/blog/pages/my` 只认 `page/size`；博客前端已按契约传 `page`，若后续有客户端传 `current` 需加 1 行兼容。

## 7. 附录：部署后冒烟脚本

仓库内提供可复现的端到端冒烟脚本：`scripts/smoke-cloud-doc.ps1`

```powershell
$env:SMOKE_ADMIN_PASSWORD='管理员测试账号密码'
$env:SMOKE_USER_PASSWORD='普通测试账号密码'
powershell -ExecutionPolicy Bypass -File scripts/smoke-cloud-doc.ps1 -Base http://127.0.0.1:19090/lizi
```

覆盖 35 项断言：登录/未登录 401、云文档新建/列表/详情/版本、baseVersion 冲突 409、覆盖 v2、博客在线编辑 v3 与冲突 409、越权 404、未绑定角色发布 403、发布后公网列表可见/详情匿名可读且 `source=TAU`、撤回后公网消失、`/blog/pages/my`、`/miniProgram/article/mine`、版本恢复、软删除、Tau 角色 grant/list/revoke、非管理员授权 403、跨设备内容一致。

> 本机实测（`lizi_cloud_smoke` 库 + 19090 端口后端）：**35/35 通过**。
> 账号要求：`tau_admin`（roles_id 含 1=管理员）、`tau_user`（普通角色）；脚本默认对 user id=2 做 Tau 角色授权/撤销，非该 id 时需改脚本参数。
> 首次运行需要库里存在 `sys_params.EXPIRE_TIME`（JWT 过期分钟），否则登录签名返回 null。
> 脚本会在「未绑定角色发布 403」前主动撤销 user 2 的 Tau 角色，保证场景可确定复现；若手工执行过授权，请注意脚本末尾会再授予一次。
