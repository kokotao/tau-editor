# Tau Editor 镜像同步脚本与 WSL 部署说明

## 脚本

`scripts/release-mirror.sh` 从 GitHub Release 获取或读取安装包，生成版本目录和 `latest.json`：

```json
{
  "version": "0.6.42",
  "tag": "v0.6.42",
  "release_url": "https://github.com/kokotao/tau-editor/releases/tag/v0.6.42",
  "generated_at": "2026-11-08T00:00:00Z",
  "assets": [
    {
      "name": "Tau.Editor_0.6.42_universal.dmg",
      "size": 123,
      "sha256": "…",
      "urls": {
        "note": "https://note.lizipro.cn/taueditor/releases/0.6.42/Tau.Editor_0.6.42_universal.dmg",
        "sourceforge": "https://sourceforge.net/projects/tau-editor/files/releases/0.6.42/Tau.Editor_0.6.42_universal.dmg/download",
        "github": "https://github.com/kokotao/tau-editor/releases/download/v0.6.42/Tau.Editor_0.6.42_universal.dmg"
      }
    }
  ]
}
```

版本目录中会写一份 `latest.json`，镜像根目录也会原子更新一份 `latest.json`。安装器可先读取根 manifest，再按 `urls.note`、`urls.sourceforge`、`urls.github` 顺序尝试。

## WSL 配置

1. 在 WSL 中准备 `curl`、`jq`、`rsync`、`ssh`。
2. 复制 `scripts/release-mirror.env.example` 到 `/etc/tau-editor/release-mirror.env`，填写 note 服务器目录、SourceForge 项目和用户名。公开 Release 的元数据和资产使用 `curl` 从 GitHub API 获取，不依赖 `gh`。
3. 将 SSH 公钥加入 note 服务器；SourceForge 使用其 SSH key，并确认能访问 FRS 上传目录。
4. 先执行 dry-run：

```bash
set -a
source ~/.config/tau-editor/release-mirror.env
set +a
bash scripts/release-mirror.sh --latest --dry-run
```

5. 验证真实上传：

```bash
bash scripts/release-mirror.sh --latest
curl -fsS https://note.lizipro.cn/taueditor/releases/latest.json | jq .
```

6. 如果不使用 1Panel 计划任务，可安装 systemd system timer（WSL 已启用 systemd 时）：

```bash
sudo cp scripts/tau-editor-release-mirror.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tau-editor-release-mirror.timer
sudo systemctl start tau-editor-release-mirror.service
```

### 日志与并发保护

systemd 服务和 1Panel Shell 计划任务都应调用
`/opt/tau-editor-release-mirror/release-mirror-runner.sh --latest`，不要直接调用
`release-mirror.sh`。包装器会：

- 将完整标准输出和错误输出同时写入 `/var/log/tau-editor-release-mirror/mirror-YYYY-MM-DD.log` 和 systemd journal；
- 使用 `/run/lock/tau-editor-release-mirror.lock` 防止 systemd 与 1Panel 重复执行；
- 将 GitHub 资产缓存到 `/var/cache/tau-editor-release-mirror/<tag>/`，同一版本且文件大小一致时记录 `CACHE_HIT`，不重复下载；
- 记录开始时间、结束状态、版本、资产大小和 SHA-256（具体资产详情由主脚本输出）；
- 失败时保留非零退出码，便于 1Panel 将任务标记为失败。
- 1Panel 的非交互 Shell 可能未设置 `HOME`；脚本在缺少 `HOME` 时使用 `/var/lib/.local/state` 作为日志目录兜底，并由包装器显式加载 `/etc/tau-editor/release-mirror.env`。
- 包装器只在主脚本退出码为 0 时输出成功；失败会保留非零退出码并打印 `[ERROR]`，避免 1Panel 误显示成功。

查看日志：

```bash
sudo journalctl -u tau-editor-release-mirror.service --since today --no-pager
sudo tail -n 200 /var/log/tau-editor-release-mirror/mirror-$(date +%F).log
```

日志轮转配置为 `scripts/tau-editor-release-mirror.logrotate`，保留 14 天并压缩。

1Panel 计划任务使用“Shell 脚本”类型，命令填写：

```bash
/opt/tau-editor-release-mirror/release-mirror-runner.sh --latest
```

迁移到 1Panel 前，先在 1Panel 中手动执行一次并确认日志、退出码和公网
`latest.json`；确认成功后再停用 systemd timer：

```bash
sudo systemctl disable --now tau-editor-release-mirror.timer
```

未完成迁移前不要同时启用两个周期任务。
