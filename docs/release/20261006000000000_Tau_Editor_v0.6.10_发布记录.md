# Tau Editor v0.6.10 发布记录

发布日期：2026-10-06（补发修复记录更新：2026-10-07）
仓库：`kokotao/tau-editor`  
发布类型：正式 GitHub Release

## 发布目标

- 更新说明在偏好设置中按 Markdown 渲染，不再直接显示 `#`、列表等原始标记。
- 修复 macOS DMG 拖拽安装界面的资源链路，确保最新蓝色背景图、应用图标、Finder 窗口布局和 Applications 拖放位置来自当前源码并完成校验。
- 补充 Apple Silicon（aarch64 / M 系列）专用 DMG，并继续提供 Intel + Apple Silicon Universal DMG。
- 将最近的偏好设置、主题、圆角、图标和工作台交互改动纳入同一版本，并同步到 GitHub Release 日志。

## 用户可见改动

### 更新说明 Markdown 渲染

- Release Notes 使用 `marked` 解析、`DOMPurify` 清理后再渲染。
- 渲染器采用动态加载，不增加设置页首屏入口体积。
- 渲染失败时回退为安全纯文本摘要。
- 增加回归测试，验证标题和列表不会以原始 Markdown 标记呈现。

### macOS DMG 拖拽安装界面

- Tauri DMG 保持当前 `dmg-background.png`、应用图标位置和 Applications 拖放位置配置，并显式生成 Finder 布局元数据 `.DS_Store`。
- GitHub Actions 在上传前挂载 DMG，校验 `.DS_Store` 非空，逐字节校验背景图和 `icon.icns`，同时检查 Universal 与 aarch64 Mach-O 架构。
- 手工打包脚本在缺少 DMG helper、Finder 布局元数据或背景资源时直接失败，避免发布无背景、旧图标或默认空白窗口的 plain DMG。

### 根因与修复

- 旧的 `v0.6.10` Universal DMG 虽然携带 `.background/dmg-background.png` 和最新 `icon.icns`，但根目录缺少 Finder 用于保存窗口布局的 `.DS_Store`。
- 在 GitHub Actions/headless 环境中，默认 Tauri DMG 流程没有可靠执行 Finder AppleScript cosmetic 步骤，导致用户看到默认深色/空白窗口，而不是源码配置的蓝色拖拽界面。
- 本次补发改为显式执行 DMG 后处理，并把 `.DS_Store` 纳入发布门禁；背景图、应用图标、Finder 布局和架构均在上传前验证。

### 偏好设置与主题体系

- 偏好设置 workspace/drawer 统一为主题风格驱动。
- 主题包和 marketplace palette 支持背景、面板及分类圆角 token。
- 圆角基础值扩展到 `0–24px`，覆盖控件、卡片、面板、标签页、弹窗和徽标。
- 设置页导航、自动保存状态、通知和工具栏图标完成一致性收口。

## 发布流程

1. 提交源码、测试、CHANGELOG、README 和本发布记录。
2. 创建并推送 `v0.6.10` 标签，触发 `.github/workflows/release.yml`。
3. GitHub Actions 并行构建 macOS Universal、macOS aarch64、Windows x64、Linux amd64 安装包。
4. 构建矩阵完成后，由 workflow 创建或更新 GitHub Release 并上传完整资产。
5. 发布完成后回读 workflow、Release 状态、资产列表、DMG 架构、`.DS_Store`、背景图、应用图标和 SHA-256，并将最终 run 与校验值回填到本记录。
