# Tau Editor 主题模式与配色市场方案

> 状态：待确认，确认后再进入实现阶段
> 日期：2026-09-28
> 范围：浅色/深色模式、主题皮肤、用户自定义配色、主题包/配色包导入、GitHub 主题市场

## 1. 背景与问题

当前浅色与深色切换时，应用背景和面板背景可能保持不变。根因是用户自定义颜色和当前主题包颜色通过 `document.documentElement.style` 写入内联 CSS 变量；内联变量优先级高于 `.light`、`.dark` 和 `skin-*` 主题选择器，因此切换模式只改变 class，背景仍被旧颜色覆盖。

当前主题包还只有单一 `mode + colors`，不能同时描述一套主题在浅色和深色下的两组颜色。激活主题包时还会直接覆盖应用模式，导致“模式选择”“主题皮肤”“自定义配色”之间的职责混杂。

## 2. 目标与非目标

### 目标

- 修复浅色/深色切换时背景、面板、文字和 Monaco 主题同步切换。
- 将主题模式与配色建立明确的关联关系。
- 浅色模式提供多种浅色配色色块，深色模式提供多种深色配色色块。
- 用户选择色块后自动切换对应主题风格，并保持系统模式逻辑可预测。
- 从“自定义配色”界面移除“应用背景”和“面板背景”配置项，避免背景锁死明暗模式。
- 提供普通用户可读的主题 JSON、配色 JSON 示例和字段说明。
- 支持从 GitHub 主题仓库浏览、下载、安装、切换、更新和删除主题/配色包。
- 支持其他用户通过 Fork + Pull Request 贡献主题包和配色包。

### 非目标

- 本阶段不执行代码改动、不创建 GitHub 仓库、不自动提交 PR。
- 不执行远程 JavaScript、CSS 或插件代码；市场只允许静态 JSON 和静态资源元数据。
- 不改变用户文档内容格式、编辑器文件格式和现有工作区数据模型。

## 3. 推荐概念模型

### 3.1 三层职责

1. **模式 Mode**：`light`、`dark`、`system`。决定当前最终明暗模式。
2. **主题风格 Skin/Family**：例如深海蓝调、森林苔原、暖日砂岩、石墨墨影、玫瑰晨曦。每个风格必须同时提供浅色和深色 palette。
3. **用户微调 Overrides**：只调整文字、强调色和状态色，不调整应用背景与面板背景。

最终颜色按以下优先级计算：

```text
resolvedTheme
  -> 当前主题风格的对应 light/dark palette
  -> 当前模式的用户自定义 overrides
  -> 可选完整主题包对应模式
  -> 对比度校验与安全回退
  -> 写入 CSS variables 和 Monaco theme
```

完整主题包可以覆盖背景和面板，但必须同时按 `light`、`dark` 分支定义；快速配色包不能覆盖背景和面板。

### 3.2 模式切换规则

- `theme = light`：固定使用浅色 palette。
- `theme = dark`：固定使用深色 palette。
- `theme = system`：跟随系统偏好，系统变化时重新计算 palette。
- 在当前模式下点击一个色块：切换主题风格/配色家族，并立即应用当前模式对应分支。
- 点击浅色色块时：将模式切换为 `light`，并应用该色块对应的浅色 palette。
- 点击深色色块时：将模式切换为 `dark`，并应用该色块对应的深色 palette。
- 设置页单独切换 `system` 时，不强行改变用户选定的主题风格；系统变更时只在同一风格下切换 light/dark 分支。
- 激活主题包不强制覆盖用户的 `theme`；主题包的 `defaultMode` 只用于首次应用时提示或作为包内默认值。

## 4. 设置页交互方案

### 4.1 主题模式

保留现有模式选择：

- 浅色
- 深色
- 跟随系统

模式选择器下显示当前实际生效模式，例如“跟随系统（当前：深色）”。

### 4.2 主题风格色块

新增“主题风格”区域，按当前实际模式展示 4 至 6 个色块卡片。每个色块至少展示：

- 背景色缩略块
- 面板色缩略块
- 主强调色
- 主题名称
- 浅色/深色标识
- 当前选中状态

建议内置色块：

浅色：

- 雾蓝白：`#eef3ff / #2563eb`
- 森林薄荷：`#edf6f0 / #1f9d64`
- 暖日象牙：`#fff7eb / #c96b0c`
- 玫瑰晨雾：`#fff1f5 / #d94678`
- 石墨银灰：`#f3f5f9 / #4b5f83`

深色：

- 深海蓝调：`#0b1020 / #7cc7ff`
- 森林苔原：`#0d1511 / #4fd28e`
- 暖日砂岩：`#16110a / #f59e0b`
- 石墨墨影：`#101216 / #8ea0bf`
- 玫瑰夜色：`#171018 / #ff8ab3`

### 4.3 自定义配色

“自定义配色”移除：

- 应用背景
- 面板背景

保留：

- 主文字
- 次级文字
- 品牌强调色
- 强品牌强调色
- 成功色
- 危险色

自定义值按模式分桶保存：

```ts
customThemeOverrides: {
  light?: {
    textPrimary?: string;
    textSecondary?: string;
    accentBrand?: string;
    accentBrandStrong?: string;
    stateSuccess?: string;
    stateDanger?: string;
  };
  dark?: {
    textPrimary?: string;
    textSecondary?: string;
    accentBrand?: string;
    accentBrandStrong?: string;
    stateSuccess?: string;
    stateDanger?: string;
  };
}
```

用户在浅色模式下修改的颜色只影响浅色分支；深色模式有独立的微调值。文字和背景对比度低于 `4.5:1` 时自动使用当前主题的安全文字色。

## 5. 主题包与配色包格式

### 5.1 完整主题包 v2

完整主题包可以定义背景、面板、文字、强调色和 Monaco 配置，必须同时提供浅色与深色分支。

```json
{
  "schemaVersion": 2,
  "type": "theme",
  "id": "ocean-mist",
  "name": "Ocean Mist",
  "version": "1.0.0",
  "author": "Your Name",
  "license": "MIT",
  "defaultMode": "light",
  "modes": {
    "light": {
      "colors": {
        "bgApp": "#eef3ff",
        "panelBase": "#ffffff",
        "textPrimary": "#162033",
        "textSecondary": "#49566d",
        "accentBrand": "#2563eb",
        "accentBrandStrong": "#1d4ed8",
        "stateSuccess": "#16a34a",
        "stateDanger": "#dc2626"
      },
      "monaco": {
        "base": "vs",
        "rules": [],
        "colors": {
          "editor.background": "#ffffff",
          "editor.foreground": "#162033"
        }
      }
    },
    "dark": {
      "colors": {
        "bgApp": "#0b1020",
        "panelBase": "#101726",
        "textPrimary": "#ecf2ff",
        "textSecondary": "#b6c2d9",
        "accentBrand": "#7cc7ff",
        "accentBrandStrong": "#4dabff",
        "stateSuccess": "#4ade80",
        "stateDanger": "#f87171"
      },
      "monaco": {
        "base": "vs-dark",
        "rules": [],
        "colors": {
          "editor.background": "#0b1020",
          "editor.foreground": "#ecf2ff"
        }
      }
    }
  }
}
```

### 5.2 快速配色包 v2

配色包只覆盖文字、强调色和状态色，不包含 `bgApp`、`panelBase`，因此不会阻止明暗模式切换。

```json
{
  "schemaVersion": 2,
  "type": "palette",
  "id": "mint-contrast",
  "name": "Mint Contrast",
  "version": "1.0.0",
  "author": "Your Name",
  "license": "MIT",
  "modes": {
    "light": {
      "textPrimary": "#10261b",
      "textSecondary": "#365c47",
      "accentBrand": "#16865a",
      "accentBrandStrong": "#0f6945",
      "stateSuccess": "#15803d",
      "stateDanger": "#b91c1c"
    },
    "dark": {
      "textPrimary": "#edfff4",
      "textSecondary": "#b9e3c8",
      "accentBrand": "#55d991",
      "accentBrandStrong": "#29b86f",
      "stateSuccess": "#4ade80",
      "stateDanger": "#fb7185"
    }
  }
}
```

### 5.3 兼容旧格式

- 继续接受现有 v1 `{ mode, colors, monaco }` 文件。
- 导入时自动迁移到 v2：旧 `mode` 的颜色放入对应分支，另一分支使用当前内置主题默认值。
- 旧 `bgApp`、`panelBase` 不迁移到快速配色 overrides；完整主题包迁移时保留到对应模式的主题分支。
- 导出统一使用 v2，并在导入结果中显示“已从旧格式迁移”。
- localStorage 中旧的扁平 `customThemeColors` 按当前 resolved mode 放入 `light` 或 `dark` 分支；旧背景/面板自定义值不再写回全局覆盖。

## 6. GitHub 主题市场方案

建议新建独立仓库：`kokotao/tau-editor-themes`。

### 6.1 仓库结构

```text
tau-editor-themes/
├── catalog/index.json
├── themes/*.json
├── palettes/*.json
├── schemas/theme-v2.schema.json
├── schemas/palette-v2.schema.json
├── examples/theme.example.json
├── examples/palette.example.json
├── previews/<id>.png
├── CONTRIBUTING.md
├── README.md
└── .github/
    ├── ISSUE_TEMPLATE/theme-request.yml
    └── workflows/validate-themes.yml
```

### 6.2 Catalog 示例

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-28T00:00:00Z",
  "items": [
    {
      "id": "ocean-mist",
      "type": "theme",
      "name": "Ocean Mist",
      "version": "1.0.0",
      "author": "Your Name",
      "license": "MIT",
      "file": "themes/ocean-mist.json",
      "preview": "previews/ocean-mist.png",
      "tags": ["blue", "light", "dark"]
    }
  ]
}
```

### 6.3 客户端功能

新增“主题市场”页面/面板，提供：

- 从 GitHub raw 地址加载 catalog。
- 主题/配色筛选。
- 浅色/深色筛选。
- 搜索名称、作者和标签。
- 查看预览、作者、版本、许可证和更新时间。
- 下载、安装、切换、更新、删除。
- 网络失败时使用最近一次缓存和内置主题。
- 提供“查看仓库”“提交主题 PR”入口，不在应用内保存 GitHub 凭证。

### 6.4 贡献流程

1. 用户从主题市场或 README 打开仓库。
2. Fork `tau-editor-themes`。
3. 复制 `examples/theme.example.json` 或 `examples/palette.example.json`。
4. 修改名称、颜色、作者、许可证和预览图。
5. 提交 Pull Request。
6. GitHub Actions 自动校验 JSON Schema、颜色格式、对比度、ID、版本和文件大小。
7. 合并后自动生成 `catalog/index.json`，客户端刷新即可看到新主题。

### 6.5 安全边界

- 只下载和解析 JSON，不执行远程 JS/CSS。
- 限制 JSON 文件大小、字段长度、颜色数量和 Monaco 规则数量。
- 只允许固定颜色字段和固定 Monaco color key。
- 禁止主题包写入文件系统、调用命令或携带可执行 URL。
- 远程 catalog 使用 HTTPS/raw GitHub 内容，并设置缓存 TTL。
- 安装前再次执行 Schema、颜色格式和对比度校验。

## 7. 分阶段实施计划

### 阶段 1：修复明暗切换与数据模型

- 将主题计算改为 `resolvedTheme -> palette -> mode overrides`。
- 移除 `bgApp`、`panelBase` 的快速自定义入口。
- 迁移旧 localStorage 和 v1 主题包。
- 增加浅色/深色切换、背景切换、对比度回归测试。

### 阶段 2：主题色块与 JSON 示例

- 设置页加入浅色/深色色块选择。
- 色块选择联动模式和主题风格。
- 新增主题包/配色包 v2 导入导出。
- 在设置页加入可复制的 JSON 示例和字段说明。

### 阶段 3：GitHub 主题市场

- 创建 `kokotao/tau-editor-themes` 仓库。
- 添加 Schema、示例、catalog、贡献模板和 CI 校验。
- 客户端增加市场浏览、缓存、下载、安装、更新和删除。

### 阶段 4：发布与回滚

- 完成单元测试、主题迁移测试、Chromium E2E 和构建。
- 先以 feature flag 或默认关闭方式发布市场功能。
- 保留旧 v1 导入能力至少一个版本周期。
- 如市场服务不可用，继续使用内置主题和本地已安装包。

## 8. 验收标准

- 浅色切换到深色时，应用背景、面板背景、正文颜色、编辑器背景同步变化。
- 深色切换到浅色时，以上颜色反向同步变化。
- 选择浅色或深色色块后，模式、主题风格和 Monaco 基础主题保持一致。
- 自定义配色页面不再出现应用背景、面板背景字段。
- 浅色和深色自定义文字分别保存，互不污染。
- 低对比度颜色自动回退，并给出可理解的提示。
- v1 主题包和旧 localStorage 可无损或有提示迁移。
- 普通用户可依据示例 JSON 创建并导入主题/配色包。
- 市场网络失败时应用不崩溃，并能使用缓存或内置主题。
- 远程主题包无法执行任意代码，非法包不会安装。
- 用户可通过 GitHub Fork + PR 提交主题并在合并后被 catalog 收录。
