# Tau Editor 主题市场 MVP 实施说明

> 日期：2026-09-28
> 状态：已实现客户端基础服务；远程仓库仍由社区按贡献流程维护。

## 1. 客户端能力

`frontend/src/services/themeMarketplaceService.ts` 提供：

- 可配置 GitHub Raw catalog 地址，默认指向 `kokotao/tau-editor-themes`。
- catalog 拉取、字段校验、24 小时 localStorage 缓存和网络失败回退。
- 主题包 URL 解析仅允许 HTTPS `githubusercontent.com`，拒绝 `http:`、`javascript:` 等地址。
- 单个 catalog 最大 512 KB，主题包最大 256 KB。
- 兼容既有 v1 主题包，并校验方案定义的 v2 `theme` / `palette` 包。
- 配色包禁止覆盖 `bgApp`、`panelBase`；完整主题包才可以定义背景和面板。
- 主题包只作为数据解析，客户端不会执行远程 JavaScript/CSS。

示例与字段说明位于 [`examples/README.md`](../../examples/README.md)。

## 2. Catalog 约定

市场仓库的 `catalog/index.json` 使用 `schemaVersion: 1`：

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-28T00:00:00Z",
  "items": [
    {
      "id": "ocean-mist",
      "type": "theme",
      "name": "Ocean Mist",
      "version": "1.0.0",
      "author": "Your Name",
      "license": "MIT",
      "file": "themes/ocean-mist.json",
      "preview": "previews/ocean-mist.png",
      "tags": ["blue", "light", "dark"]
    }
  ]
}
```

`file` 和 `preview` 使用相对路径，由客户端基于 catalog URL 解析；远程地址必须来自 HTTPS GitHub Raw。

## 3. 社区贡献流程

1. Fork 主题市场仓库，并复制 `examples/themes/theme.example.json` 或 `examples/palettes/palette.example.json`。
2. 修改 `id`、名称、作者、许可证、颜色和可选预览图；不要加入脚本、HTML 或 CSS。
3. 在 `themes/` 或 `palettes/` 下新增 JSON，并在 `catalog/index.json` 增加条目。
4. 本地执行 JSON 校验和 `pnpm typecheck`，确认 id、颜色、模式和文件大小符合限制。
5. 提交 Pull Request。维护者审核可读性、许可证、预览图和对比度后合并。
6. 合并后重新生成 catalog，Tau Editor 刷新市场即可获得新包。

贡献者不需要向客户端提供 GitHub Token；应用只打开仓库或 PR 页面，不在本地保存凭据。

## 4. 回滚与失败处理

- catalog 请求失败时优先使用最近 24 小时缓存；缓存无效则保留内置主题和本地已安装主题。
- 主题包校验失败不会写入设置，也不会改变当前主题。
- 如远程仓库结构发生变化，只需将 catalog URL 指向兼容的 `index.json`；客户端无需更新即可恢复到旧市场。
