# Tau Editor v0.3.0 自适应一体工作台规格

## 1. 目标与范围

v0.3.0 将 Tau Editor 升级为本地优先的写作与代码工作台。产品保留左侧项目区、中间内容区、右侧上下文区的扁平三栏布局；右侧能力由当前文件类型和用户任务驱动，而不是要求用户在“写作模式”和“开发模式”之间切换。

本版本一次性交付八项能力：

1. 工作区、标签页、光标与未保存草稿恢复。
2. 外部文件变更检测、对比和安全处理。
3. 大文件分块读取、追加加载和截断保护。
4. 工作区全局搜索与安全替换。
5. 快速打开、命令面板、最近工作区。
6. Git 变更列表、行级 Diff 与基础暂存操作。
7. 代码上下文：文件符号、问题与测试入口。
8. 写作增强：图片资源、链接关系、任务聚合、HTML 导出。

非目标：不在本版本实现远程同步、协作编辑、完整调试器、通用插件市场或全语言 LSP。代码上下文应采用可替换的 Provider 接口，为后续 LSP 保留入口。

## 2. 核心交互

### 2.1 固定框架

- 左侧：文件树、全局搜索结果、Git Changes、最近工作区和工作区任务。
- 中间：当前文件、搜索结果定位、Markdown 预览或 Diff。
- 右侧：按上下文显示 Markdown 大纲/任务/链接、代码符号/问题/测试、项目搜索/变更，或恢复/冲突处理。
- 顶部：`⌘P` 快速打开，`⌘⇧P` 命令面板，`⌘⇧F` 全局搜索。

现有小屏抽屉规则保持不变；新增面板只能复用左侧或右侧抽屉，不可为单独功能创建容器式页面。

### 2.2 上下文优先级

1. 未解决的恢复或外部修改冲突优先显示内容安全提示。
2. 正在执行的搜索或替换显示项目上下文。
3. 代码文件显示符号、问题、测试入口。
4. Markdown 文件显示大纲、任务、链接和资源。
5. 其他文本文件保留现有大纲或基础文件信息。

用户可以手动折叠右侧栏，但不会永久失去未解决冲突的入口。

## 3. 模块与契约

### 3.1 会话与草稿恢复

现有 `text-editor-session-v1` 只用于旧版读取；v0.3.0 新增唯一的本机恢复库，固定存放在 Tauri `app_data_dir/recovery-v2/`。会话索引为 `session.json`，草稿为 `drafts/<sha256(path)>.json`，不再把所有标签内容直接写入浏览器 `localStorage`。

`SessionSnapshotV2` 固定字段：`version: 2`、`savedAt`、`workspacePath`、`activeTabPath`、`openTabs[{path, viewState, pinned}]`、`layout`、`recentWorkspaces`。`DraftRecordV2` 固定字段：`version: 2`、`path`、`baseFingerprint{mtimeMs,size}`、`content`、`updatedAt`、`cursor`、`scrollTop`。旧 v1 快照只迁移路径、活动标签和可安全解析的布局；迁移成功后删除 v1，解析失败时忽略并启动默认工作区。

恢复库保留最多 30 天、40 个草稿和 32MB 文本，超出时按最旧记录清理；用户可从恢复面板单项恢复、丢弃或清空全部。恢复索引读取/写入失败不得阻止应用启动。

- 正常保存后删除对应草稿。
- 应用启动时对比草稿与磁盘指纹；仅显示仍有价值的恢复项。
- 用户可逐项“恢复”“丢弃”或批量处理。
- 路径与内容不写入浏览器云端；固定仅保存至本机应用数据目录。

### 3.2 文件变更保护

文件元数据使用 `mtime + size` 指纹，必要时回退到内容哈希。每个可编辑标签保留打开时基线 `{fingerprint, content}`；外部变更后的比较固定为三方：打开时基线、当前内存内容、当前磁盘内容。对全部打开文件建立观察；文件变更事件去抖后分为：

- 当前无本地改动：可自动提示重新加载。
- 当前有本地改动：禁止自动覆盖，显示“保留当前 / 重新加载 / 查看 Diff”。
- 文件被删除或移动：保留内存内容，明确显示路径状态并提供另存为。

`查看 Diff` 使用 Monaco DiffEditor：原始侧为当前磁盘内容，修改侧为内存内容；本版本不自动合并。选择“重新加载”仅在用户确认后替换内存、更新基线和删除对应草稿；选择“保留当前”只更新冲突状态，不更新基线。部分加载的大文件不进入 Diff，仅可“继续加载后比较”“重新加载”或“另存为”。

### 3.3 大文件能力

后端已有 `read_file_chunked`、行范围读取和大文件配置命令；本版本把前端服务接入真实命令，消除仅预留调用的降级路径。

- 状态机固定为 `initial -> loading -> complete | failed | cancelled`。第一屏加载固定安全块，后台顺序追加后续块。
- 超出高亮阈值时关闭高成本特性，状态栏说明原因。
- `loading` 状态编辑器只读、禁用保存与格式化；`complete` 后才允许编辑与覆盖保存。用户取消或失败后只可重试、重新加载或另存为首屏内容，绝不覆盖原文件。
- 分块边界不得产生 UTF-8 截断或 offset 死循环。

每次加载携带单调递增 `loadSessionId`；关闭标签、重新打开或发起新加载会废弃旧会话结果。`offset` 必须以返回的 `offset + size` 推进；达到 `totalSize` 才可转为 `complete`。

### 3.4 全局搜索与替换

新增可取消的项目搜索服务。优先使用受控 Rust 遍历与正则实现，支持路径过滤、大小写、全词、正则；搜索结果返回文件、行号、列号、预览和匹配范围。

替换流程固定采用“按文件独立提交”，不宣称跨文件事务：预览命中 -> 用户选择文件/命中 -> 每个候选文件写入前验证原始指纹 -> 单文件原子写入 -> 汇总成功、跳过和失败结果。外部变更文件在写入前跳过，不影响已成功写入的已确认文件；结果页可逐项重试，撤销使用每个成功文件的内存前镜像并再次要求指纹匹配。无效正则、取消搜索或用户未确认时不写入任何文件。

`preview_replace` 返回不可猜测的 `previewId` 和每个文件的 `ReplacementPlan`：`{relativePath, expectedRevision, operations:[{matchId,startByte,endByte,originalSha256,replacement}]}`。同一文件操作按 `startByte` 严格升序、互不重叠；后端应用时再次读取原文，验证 revision、范围、原片段 hash 和排序，再从尾部向前替换。任一校验失败，该文件返回 `FILE_CONFLICT` 或 `INVALID_REPLACEMENT_PLAN`，不会写入。

### 3.5 快速工作流

`QuickOpen` 索引工作区文件和最近文件；命令面板注册命令、快捷键和可见性条件。最近工作区最多保存 12 项，支持固定和移除。

### 3.6 Git 上下文

新增受限 Git 服务，只允许在已选择工作区根目录中执行：状态、文件 Diff、暂存、取消暂存、丢弃单文件改动。丢弃操作必须先二次确认且不允许影响未跟踪文件；不存在 Git 或命令失败时显示可恢复错误。所有子进程使用参数数组而非 shell 字符串，超时 15 秒，禁止访问工作区外路径。

### 3.7 代码上下文

新增 `ContextProvider` 接口：`supports(document)`、`getSections(document)`、`getActions(document)`。Markdown、JSON/YAML、代码文件分别实现 Provider。

代码 Provider 第一阶段使用 Monaco 文档符号与现有语言服务能力；显示符号、语法/模型诊断和项目中测试文件快捷入口。LSP 仅作为后续 Provider，不改变 UI 契约。

### 3.8 写作增强

- 图片资源：拖入或通过原生文件选择器选择图片后复制到同级 `assets/`（用户确认后），插入相对 Markdown 链接；复制失败不修改文档。外部源文件永远不直接作为前端命令参数，而是由本机原生选择/拖放事件换取一次性授权令牌。
- 链接关系：解析当前工作区 Markdown 相对链接，区分有效、失效、外链并提供跳转。
- 任务聚合：识别 `- [ ]` 与 `- [x]`，右侧展示当前文档和工作区任务并可精确跳转。
- HTML 导出：使用现有 Markdown 渲染与净化规则导出单一 HTML 文件；导出前校验目标路径。

## 4. 错误、数据和安全边界

- 所有 Tauri 文件/Git 命令先执行 `resolve_workspace({ path })`，得到仅本次运行有效的 `workspaceId` 与 canonical 根目录。后续命令只接收 `workspaceId + relativePath`，拒绝空路径、目录穿越、NUL 字符和符号链接逃逸；渲染端不可直接传任意绝对路径到工作区、搜索、Git、资源和导出命令。
- 搜索、分块读取、Git 和导出命令返回结构化错误码与用户可读消息：`WORKSPACE_NOT_FOUND`、`PATH_OUTSIDE_WORKSPACE`、`SYMLINK_ESCAPE`、`FILE_NOT_FOUND`、`FILE_CONFLICT`、`INVALID_PATTERN`、`TOO_LARGE`、`OPERATION_CANCELLED`、`GIT_REPOSITORY_NOT_FOUND`、`GIT_CONFLICT`、`IO_ERROR`。
- 会话恢复、草稿、最近记录均提供清理入口。
- 异步搜索、文件监听和右侧 Context Provider 都需使用请求序号或 AbortController，旧结果不得覆盖新文件状态。
- 所有写入使用原子写入；批量替换中单文件失败需保留已完成列表并说明失败文件。

### 4.1 Tauri 命令契约

新增命令固定如下；所有路径必须经过工作区根目录校验，成功响应包含 `requestId`，前端只接收仍为当前的请求结果。

| 命令 | 请求 | 成功响应 |
|---|---|---|
| `resolve_workspace` | `{ path }` | `{ workspaceId, rootPath }` |
| `get_file_revision` | `{ workspaceId, relativePath, includeHash? }` | `{ requestId, exists, size, modifiedMs, revision }` |
| `list_recovery_records` | `{}` | `{ requestId, session, drafts }` |
| `write_recovery_record` | `{ session?, draft? }` | `{ requestId }` |
| `delete_recovery_record` | `{ path? , all? }` | `{ requestId, deleted }` |
| `watch_workspace` / `unwatch_workspace` | `{ workspaceId, ignore? }` / `{ watchId }` | `{ watchId }` / `{ requestId }` |
| `read_file_chunk` | `{ workspaceId, relativePath, offset, byteLength, expectedRevision? }` | `{ requestId, content, offset, bytesRead, nextOffset, totalSize, revision, isLast }` |
| `write_file_if_revision` | `{ workspaceId, relativePath, content, expectedRevision }` | `{ requestId, revision }` |
| `search_workspace` | `{ workspaceId, query, options, requestId }` | `{ requestId, searchId, matches, truncated, scannedFiles, skipped }` |
| `cancel_request` | `{ requestId }` | `{ requestId, cancelled }` |
| `preview_replace` | `{ workspaceId, searchId, replacement, selectedMatchIds, requestId }` | `{ requestId, previewId, plans }` |
| `replace_workspace_files` | `{ workspaceId, previewId, replacements[{relativePath,expectedRevision,operations}], requestId }` | `{ requestId, succeeded, skipped, failed }` |
| `git_open_repository` | `{ workspaceId }` | `{ repoId, rootPath, branch, headOid }` |
| `git_status` | `{ repoId, requestId }` | `{ requestId, branch, entries }` |
| `git_diff` | `{ repoId, relativePath, staged, requestId }` | `{ requestId, diff, isBinary, truncated }` |
| `git_stage` / `git_unstage` / `git_discard` | `{ repoId, relativePaths, expectedHead, requestId }` | `{ requestId, status }` |
| `open_import_asset_dialog` | `{}` | `{ assetGrantId, fileName }` |
| `import_markdown_asset` | `{ workspaceId, documentPath, assetGrantId }` | `{ requestId, relativePath }` |
| `open_export_destination_dialog` | `{ suggestedName }` | `{ destinationGrantId }` |
| `export_markdown_html` | `{ workspaceId, relativePath, destinationGrantId, html }` | `{ requestId, path }` |

文件 revision 固定为 `mtimeNs:size`；需要强校验时另附 BLAKE3 内容哈希。`write_file_if_revision` 在 revision 不一致时返回 `FILE_CONFLICT` 与当前元数据，使用随机同目录临时文件、`fsync` 和 `rename` 完成原子替换。文件事件通过 `workspace://fs-changed` 推送 `{ watchId, changes[{kind,path,oldPath?,revision?}] }`；后端聚合去抖并过滤 `.git`、`node_modules`、`target` 和自身临时文件，前端仍以 revision 作最终判断。

`search_workspace` 为一次可取消搜索建立不可猜测的 `searchId` 和只读结果快照；快照仅保存在应用内存，首次 `preview_replace`、取消或 5 分钟空闲后清理。`preview_replace` 接收失效/不存在的 searchId 时返回 `SEARCH_EXPIRED`，不回退到重新搜索。`cancel_request` 将 requestId 写入应用内取消表；长搜索每 256 文件、替换预览每 128 个命中检查该表，并在成功、失败或取消 60 秒后清理。Tauri 调用不可强制中止时，前端仍以递增 `requestId` 丢弃过期响应，取消表负责释放后端工作。`assetGrantId` 和 `destinationGrantId` 只能由原生选择/保存对话框或经 Tauri 验证的拖放事件创建，只能使用一次、5 分钟后失效，后端保存 canonical 路径且不会把绝对路径返回给前端。既有 `read_file_chunked` 和 `write_file_chunked` 会迁移到上述工作区/revision 契约；读块最大 4MiB，分段保存使用 staged write，只有 `commit(expectedRevision)` 成功后才可替换原文件。

## 5. 测试与验收

### 功能验收

1. 关闭并重启应用可恢复工作区、标签、活动文件和草稿；恢复与丢弃均可完成。
2. 外部修改已打开文件时，未保存内容不会被覆盖，并可进入 Diff 或重新加载。
3. 100MB UTF-8 文本可首屏打开并继续追加；partial 文件不可直接覆盖保存。
4. 搜索能定位跨文件命中；替换预览、取消、异常和原子写入路径可验证。
5. `⌘P`、`⌘⇧P`、`⌘⇧F` 在 macOS 可用，且不与编辑器快捷键冲突。
6. Git 工作区能查看状态和单文件 Diff；危险操作有确认。
7. Markdown 与 TypeScript 打开后右侧均提供相应上下文，切换文件时不出现过期内容。
8. 图片、链接、任务和 HTML 导出均可在真实工作区完成；失败时原文保持不变。

### 质量门槛

- 新增服务具备单元测试，Tauri 命令具备 Rust 测试。
- 补充至少一条 Playwright/Tauri 关键路径：恢复、搜索替换、外部修改或 Git Diff。
- `pnpm typecheck`、`pnpm test:unit`、`pnpm build`、`cargo test`、`cargo check` 和 `pnpm tauri build` 必须通过。
- 版本号统一升级到 `0.3.0`，生成 macOS 安装包，推送分支、合并主分支、创建 `v0.3.0` GitHub Release 并上传产物。

## 6. 迁移与回滚

旧版本的设置与布局键保持兼容；新增持久化数据带版本号，读取失败时回退默认工作区而非阻塞启动。GitHub Release 保留 v0.2.6；如 v0.3.0 发现阻断问题，用户可下载旧版或发布修复 tag，绝不覆盖已发布的 tag 与安装包。
