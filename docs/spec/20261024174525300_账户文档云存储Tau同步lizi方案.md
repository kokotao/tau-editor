# 账户文档云存储（Tau ⇄ lizi）整体方案

> 版本：v1.1（规划稿）
> 日期：2026-10-25
> 仓库：`text-editor`（Tau 编辑器）+ `lizi-project`（lizi-learning-management 后端）
> 状态：待评审，未进入开发

## 1. 目标与非目标

### 1.1 背景

Tau 编辑器当前是纯本地文件编辑器，无账号、无网络同步：

- 前端 `frontend/src/stores/settings.ts` 用 `localStorage` 保存设置，未接入账号/云配置位点；
- 文件读写走 Tauri 命令，本地工作区由 `workspace` / `fileSystem` / `tabs` 等 Pinia store 维护；
- Rust 侧 `frontend/src-tauri/Cargo.toml` 已依赖 `reqwest 0.12`（json + rustls-tls + stream），具备网络能力但尚未接云服务。

lizi-project 已具备完整 C 端账号与安全链路：

- 微信小程序登录 `WChatController#queryOpenId`，JWT 写入响应头 `X-Authorization-Lizi` / `Refresh-Authorization`；
- `JwtAuthenticationFilter` 统一校验 JWT、账户状态、登出黑名单并装载 `SecurityContext`；
- `SecurityConfig.PUBLIC_PATHS` 仅对指定端点放行（如 `/wx/**`、`/miniProgram/member/plans`、`/miniProgram/member/me`），其余 `anyRequest().authenticated()`；
- 业务侧统一用 `SystemTokenUtil.geUserInfoFromToken()` 从 `SecurityContext` 取 `SysUser`，云存储接口沿用该约定；
- 已有多文件上传能力（`StaticResourceController#upload` / `FileUtil.uploadFile` / `GlobalStaticVariables.SYS_DATA_URL`），服务端配置 `max-file-size: 1024MB`。

注意：现有 `/file/**` 是**公开静态资源映射**（`WebMvcConfig`），云存储私有内容不能直接落在该目录下用裸 URL 暴露，必须走「不可预测 storage_key + Controller 鉴权流」。

因此本功能是给 Tau 增加「账号登录 + 文档云同步」，复用 lizi 现有账号体系与上传基础设施，而不是新建一套云盘平台。

### 1.2 目标

1. Tau 用户可用同一 lizi 账号登录，凭据安全保存在本机（Keychain / DPAPI / libsecret），Web 版可降级为会话内内存 token。
2. 用户可手动选择同步文件夹或同步当前打开文档；同步粒度、文件类型白名单、冲突策略可配置。
3. 云端保存文档历史版本（按内容哈希 + 时间线），支持从云端拉取、跨设备恢复。
4. 服务端按用户隔离存储，接口鉴权复用 JWT；全链路 HTTPS、敏感信息不落日志。
5. 云端文档支持「分类/栏目」元数据，同步后可在 lizi 博客在线栏目中按分类/标签查看，并可在线查看/编辑。
6. 同步的文档可作为「我的文章」展示在 lizi 博客首页（登录后可见自己的私有文档，也可显式「分享公开」成为公网文章）。
7. Tau 登录账号绑定 lizi 独立的「Tau 作者」角色，文章以该账号身份发布，同时可被博客首页与小程序文章接口消费。
8. 文档可通过 lizi 现有 `/miniProgram` 体系扩展为学习文档中心（后续可选：文章发布、知识图谱关联、AI 检索）。

### 1.3 非目标（V1 不做）

- 不做实时协同编辑（多人同时编辑同一文档、OT/CRDT）。
- 不做全盘文件系统镜像同步（只同步用户显式加入同步范围的文件/文件夹）。
- 不做公开网盘/分享链接（V2 可做只读分享）。
- 不做对象存储迁移改造：V1 用本地磁盘目录 + 文件表，但一开始就抽象成 `DocumentStorage` SPI（`LocalDocumentStorage` 实现），接入 MinIO/OSS 只换实现不换 Controller。
- 不做历史版本数无限保留：V1 每文件最多保留 N 个版本（默认 30），可配置。
- 不做多人实时协同编辑（在线编辑以「保存即覆盖 + 版本号校验」实现，不引入 WebSocket/CRDT；多人协同留到 V2）。
- 不做公网文章/博客的自动发布审核流：V1 的「分享公开」是显式发布操作，文档转为 `article` 已发布状态，直接出现在博客首页公开列表。
- 不新建一套 Tau 独立用户体系：Tau 登录继续映射 lizi `sys_user`，角色只做授权与内容归属，不复制账号。
- 不默认使用一个共享的「Tau 机器人账号」承载所有用户文章：这会破坏「我的文章」与作者归属；共享服务账号仅用于后台自动化发布场景，不作为 Tau 用户登录账户。

| Tau Rust | `cloud_sync` 模块（新增） | 安全凭据存取、网络请求、分块上传、哈希计算 |

| lizi 权限 | `role` / `role_permission` / `sys_user.roles_id` | 新增「Tau 作者」角色；`roles_id` 追加角色 ID，发布接口按角色 + 文章 owner 双重校验 |

### 3.2 同步数据流

```text
[Tau 本地文件] --read/hash--> [CloudSyncQueue] --upload(versioned)--> [lizi API]
[lizi API]      --list/metadata--> [CloudSyncQueue] --download/diff--> [Tau 本地文件]
冲突检测：以 (fileId, baseVersion, contentHash, mtime) 做三方比较；
无冲突：更新本地 + 云端元数据；有冲突：进入冲突面板，用户决策后重放。
```

在线栏目与博客发布数据流：

```text
[Tau 云文档] --category/tags/visibility--> [CloudDoc API]
[CloudDoc API] --在线栏目查询--> [博客在线栏目页 / 在线编辑页]
[用户「分享公开」] --publish--> [article 已发布(status=1, authorId=userId, category/tags)]
[博客首页] --/blog/pages/list?authorId=me|public--> [我的文章 / 公网文章列表]
```

### 3.3 接口前缀与安全

推荐接口前缀：`/miniProgram/cloud/docs/**`（别名 `/miniProgram/note/**` 可选）

- `GET  /miniProgram/cloud/docs/me`：查询云端空间信息（配额、使用量、已同步文件数）
- `GET  /miniProgram/cloud/docs`：云端文件树（分页，含 `fileId / path / version / contentHash / size / updatedAt`）
- `POST /miniProgram/cloud/docs`：创建/更新文件（multipart 或 JSON+分块）
- `GET  /miniProgram/cloud/docs/{fileId}`：下载文件内容（Controller 鉴权流，不暴露裸文件 URL）
- `GET  /miniProgram/cloud/docs/{fileId}/versions`：历史版本列表
- `POST /miniProgram/cloud/docs/{fileId}/versions/{versionId}/restore`：恢复指定版本
- `DELETE /miniProgram/cloud/docs/{fileId}`：软删除

在线栏目/在线编辑/博客发布接口（复用现有博客链路，前缀 `/blog/pages/**`）：

- `GET  /blog/pages/my`：登录后的「我的文章」列表（`authorId=当前用户`，含私有草稿 `status=0` 与已发布 `status=1`）
- `GET  /blog/pages/cloud/{docId}`：在线查看/编辑一篇云文档（未公开时仅 owner 可见）
- `PUT  /blog/pages/cloud/{docId}`：在线编辑保存回写（版本号校验，owner 专属）
- `POST /blog/pages/cloud/{docId}/publish`：显式「分享公开」，生成/更新 `article`（`status=1`）并关联云文档
- `POST /blog/pages/cloud/{docId}/withdraw`：撤回公开，`article` 置回私有/草稿
- `GET  /blog/pages/categories` / `/blog/pages/tags`：现有分类/标签，新增云文档后自动纳入索引
- `GET  /miniProgram/article/mine`：登录态「我的文章」（`authorId=当前用户`，含草稿/已发布；仅本人可见）
- `GET  /miniProgram/article/list`：保持现有公开接口，只返回 `status=1`；Tau 作者已发布文章自动纳入 `ids`/`category` 查询

鉴权：

- 新接口默认**不加入** `PUBLIC_PATHS`，由 `anyRequest().authenticated()` 兜底；如需游客匿名草稿，仅单列公开端点并在 Controller 内用 `X-Device-Id` 降级（对齐 `MemberController /me` 模式）；
- 每次请求校验 `X-Authorization-Lizi` JWT，服务端读取 `SysUser.id` 作为资源 owner；
- 文件归属校验：所有操作按 `user_id` 过滤，禁止跨用户访问；
- 特别地，`/blog/pages/**` 已在 `SecurityConfig.PUBLIC_PATHS` 中整体放行，因此 `/blog/pages/my`、`/blog/pages/cloud/{docId}` 的写操作与私有读取，必须在 Controller 内用 `SystemTokenUtil.geUserInfoFromToken()` 强制校验登录与 owner；仅 `visibility=PUBLIC` 的文档允许未登录只读访问，公开文章仍走现有 `/blog/pages/article/{id}`。
- `/miniProgram/article/**` 为公开路径，新增的 `/miniProgram/article/mine` 必须在 Controller 内校验登录；公开列表/详情仍只返回 `status=1`，不得返回用户私有草稿。

分类/栏目建模：

- 博客现有 `category` 表为多级树（`id/name/parent_id/sort/children`，服务端 `CategoryService.getCategoryTree()` 返回树），`/blog/pages/categories` 已返回该树；
- `user_document.category` 存叶子分类名称（与现有 `article.category` 字符串保持一致），另加 `category_id` 存树节点 ID，便于在线栏目按父级聚合；
- 在线栏目页复用首页既有 `el-cascader` 分类筛选与标签筛选，数据源仍为 `/blog/pages/categories|tags`。

Tau 角色建模：

- lizi 实际角色表是 `role`（`id/role/descr/create_time/update_time`），不是 `sys_role`；`sys_user.roles_id` 存逗号分隔的角色 ID 字符串（现有默认角色为 `2`）；
- 新增角色 `Tau 作者`，用于标识「可通过 Tau 发布文章」的账号；角色绑定由后台/邀请审批完成，**不允许 Tau 客户端自报角色**；
- 角色只授予文章创作与发布能力，不授予后台管理菜单；管理员仍保留全量管理权限；
- 绑定后 `roles_id` 形如 `2,8`（保留用户原有通用角色，追加 Tau 角色 ID），不覆盖现有角色。

### 3.4 存储模型

新增 3 张表（可执行 DDL 放 `lizi-learning-management/sql/`，按会员支付表风格编写；版本表结构对齐现有 `article_history` 的「version + 内容/文件路径」模式）；在线栏目与博客发布直接复用现有 `article` / `article_history` / `category` / `tags` 链路，不另建博客文章表：

| 表 | 职责 | 关键字段/约束 |
|---|---|---|
| `user_document` | 账户文档元数据 | `id`、`user_id`、`path`、`title`、`content(MEDIUMTEXT)`、`storage_key`、`content_hash`、`size`、`version`、`status`、`is_deleted`、`created_at/updated_at`；`uk(user_id,path)` |
| `user_document_version` | 文档历史版本 | `id`、`document_id`、`version`、`content`、`storage_key`、`content_hash`、`remark`、`created_at`；`uk(document_id,version)` |
| `user_document_sync_log` | 同步审计/断点 | `id`、`user_id`、`document_id`、`action`、`client_device_id`、`status`、`error_msg`、`created_at`；`idx(user_id,status,created_at)` |

字段补充：`user_document` 增加 `category`（分类）、`tags`（逗号分隔）、`visibility`（PRIVATE/PUBLIC）、`published_article_id`（关联 `article.id`，分享公开后回填）。

`article` 增补字段（增量 DDL，兼容存量数据）：

- `source VARCHAR(32) NOT NULL DEFAULT 'ADMIN'`：内容来源，Tau 发布写 `TAU`，便于统计/审计；
- `publish_channels VARCHAR(32) NOT NULL DEFAULT 'BLOG,MINI'`：发布渠道，默认双端可见；如后续要单独控制博客/小程序，可按渠道过滤；
- `author_id` 继续复用现有字段，Tau 发布写 `sys_user.id`，`author` 写 `sys_user.username`。

文件内容存放：

- 通过 `DocumentStorage` SPI：`LocalDocumentStorage` 落盘 `${SYS_DATA_URL}/cloud/{userId}/docs/{documentId}/{version}/`，仅在 `user_document` 记录 `storage_key`（不可预测），**不**走公开 `/file/**` 映射；
- 每次上传写新版本目录，元数据表只记录当前 `contentHash/version`；V2 换 MinIO/OSS 只新增 `MinioDocumentStorage` 实现。

## 4. 关键流程

### 4.0 Tau 侧最小改动点（勘察结论）

1. Rust 层：新增 `frontend/src-tauri/src/commands/cloud_sync.rs`（或 services 模块），提供 `cloud_login / cloud_logout / cloud_sync_now / cloud_get_state` 等命令，内部封装安全凭据存取（macOS Keychain / Windows DPAPI / Linux libsecret）与 `reqwest` HTTP 调用，并在 `lib.rs` 注册；Tauri 侧目前**没有** keychain/HTTP 命令，`reqwest` 已存在可复用（`Cargo.toml`）。
2. 前端服务：新增 `frontend/src/services/cloudSyncService.ts` + `frontend/src/stores/cloudSync.ts`，在 `lib/tauri.ts` 增加 `cloudSyncCommands` 封装；纯浏览器通过现有 `isTauriApp()` 判断降级为会话内内存 token。
3. 挂接点：云同步挂在自动保存（`App.vue`）、会话恢复（`sessionService`）、外部变更（`externalFileSync`）三条路径；Tab 的 `lastKnownModified / fileRevision / externalModifiedAt` 可直接作为本地基线（`stores/tabs.ts`）。
4. 冲突复用：直接扩展既有 `externalFileSync.ts` 的三态决策、`stores/fileConflicts.ts` 冲突 store 与 `diffService.ts` 只读 Diff 会话，实现本地 vs 云端三方合并预览。
5. 配置与 i18n：`SettingsPanel` 新增「云同步」分类，`commandRegistry` 注册 `cloud.login / cloud.logout / cloud.syncNow`，并补齐 `i18n/ui.ts` 中英 key。
6. 同步白名单：复用 `workspaceService.ts:58-74` 的大文件/二进制判断（12MB 阈值 + `pdf/doc/docx/xls/xlsx/db/sqlite/sqlite3` 集合），默认只同步文本可编辑内容。

### 4.1 登录

1. Tau 设置页点击「登录 lizi 账号」；
2. 调用现有登录接口（微信小程序 `WChatController#queryOpenId` code 登录，或预留账号密码接口），拿到 `X-Authorization-Lizi` / `Refresh-Authorization`；
3. Tau Rust `cloud_sync::credentials` 用系统钥匙串存储 token；Web 版存内存；
4. 登录后调 `GET /miniProgram/cloud/docs/me` 校验 token 与空间，前端进入同步主界面。

### 4.2 同步

1. 用户把本地文件夹加入同步范围（或「同步当前文档」）；
2. 前端扫描并计算文件哈希，与服务端 `GET /files` 元数据对比；
3. 服务端缺失/版本落后：按内容分块上传（默认 8MB/块），`user_document_version` 记录版本；
4. 服务端更新/本地缺失：拉取内容写本地，写入 `externalFileSync` 兼容的 mtime；
5. 本地/云端均变化且 hash 不同：标记冲突，进冲突面板；
6. 完成/失败写入同步日志，Tau 状态栏显示进度。

云文档同时维护 `category/tags/visibility`：

- 同步时把文档属性（分类/标签/可见性）一并上传，Tau 编辑时可编辑 frontmatter 或属性面板；
- 云端按 `category_id/category` / `tags` 建索引，博客在线栏目页按分类/标签查询（复用 `/blog/pages/categories|tags` 数据源）；
- Tau 属性面板从 `/blog/pages/categories` 拉取多级分类树，用户选择叶子分类后同步 `category_id/category` 两个字段。

### 4.3 在线栏目与在线编辑

1. 博客首页/栏目页提供「我的文章」入口：登录态下调用 `/blog/pages/my`，展示 `authorId=当前用户` 的云文档/文章；
2. 未登录访问在线栏目：只展示已公开（`visibility=PUBLIC` 且 `article.status=1`）的文章；
3. 在线编辑页 `GET /blog/pages/cloud/{docId}`：拉取云端最新内容，仅 owner 可编辑；保存用 `PUT` 带 `baseVersion`，冲突返回 409 提示刷新/合并；
4. 在线编辑保存后回写 `user_document` 并递增版本；若已公开，同步更新关联 `article`，并可选写 `article_history` 新版本；
5. 「分享公开」按钮：显式发布 → 通过 `ArticleService` 创建/更新 `article`（`authorId=userId`、`title/content/summary/category/tags/status=1`），回填 `user_document.published_article_id`；可选写入 `article_history` 新版本；
6. 「撤回公开」按钮：`article.status` 置回草稿/下线，但云文档本身保留。

### 4.4 博客首页分流

- 公网首页 `/blog/pages/list` 保持现有行为：只查 `status=1` 已发布文章（不泄露私有草稿）；
- 登录态在博客首页新增「我的文章 / 全部公开」视图切换：`/blog/pages/my` 返回自己的私有 + 已发布文档；公开视图仍走现有 `/blog/pages/list`；
- 新版首页 `newpage/index.vue` 在现有 `keyword/category/tag/sort` 筛选面板上方或右侧增加分段入口：登录后显示「我的文章」，未登录仅显示公开视图；
- 详情/在线编辑路由需鉴权：未登录访问私有云文档返回 401/404，公开文章走现有 `/blog/pages/article/{id}`。

### 4.5 Tau 角色登录与双端发布

1. Tau 登录复用 lizi 账号（微信/账号密码按现有登录方式），首次使用 Tau 发布需由后台管理员或邀请码授予「Tau 作者」角色，客户端不得自行声明角色；
2. 登录后 `roles_id` 带上 Tau 角色 ID；Tau 前端通过 `/blog/pages/my` 判断是否具备发布能力，未绑定角色时只允许私有云同步；
3. 显式「分享公开」时服务端校验：当前用户 `roles_id` 包含 Tau 角色或管理员角色，且目标 `user_document.user_id = currentUserId`；
4. 发布写 `article`：`authorId=currentUserId`、`author=username`、`source='TAU'`、`publish_channels='BLOG,MINI'`、`status=1`、`category/tags` 从云文档同步；
5. 博客首页 `/blog/pages/list` 与小程序 `/miniProgram/article/list` 均已按 `status=1` 查询，因此发布后自动双端可见；私有文档不写 `article`，不会出现在任一公开列表；
6. 撤回公开时 `article.status=0`（或软删除），双端同时下线；云文档与历史版本保留；
7. 预留共享自动化账号：若后续需要 CI/批量发布，可创建独立 `TAU_SERVICE` 服务账号，仅用于机器发布，不与用户登录账号混用。

### 4.6 冲突处理

复用 Tau 已有能力：

- `services/externalFileSync.ts` 的 mtime 决策；
- `services/diffService.ts` / `stores/fileConflicts.ts` 的三路 diff；
- 冲突面板提供：本地覆盖云端、云端覆盖本地、手动合并（编辑后上传新版本）。

## 6. 数据模型与 SQL（落点）

- DDL 文件：`lizi-learning-management/sql/20261024174525300_add_user_document_tables.sql`
- 全部 `CREATE TABLE IF NOT EXISTS`，utf8mb4，幂等可重跑；
- 使用 `user_id` 索引，`uk(user_id,path)` 防重复路径；
- 软删除 `is_deleted`，删除时保留版本表；V1 不物理清理文件内容，提供后台清理脚本（V2）。

角色增量脚本：`lizi-learning-management/sql/20261025_add_tau_author_role.sql`

```sql
-- 幂等新增 Tau 作者角色（role 表无 role 唯一键，使用 NOT EXISTS 守卫）
INSERT INTO `role` (`role`, `descr`, `create_time`, `update_time`)
SELECT 'Tau 作者', 'Tau 编辑器作者：可发布/编辑本人文章，文章双端可见', NOW(), NOW()
WHERE NOT EXISTS (SELECT 1 FROM `role` WHERE `role` = 'Tau 作者');
```

- `sys_user.roles_id` 的追加由后台审批/邀请流程完成，使用「读取现有值 → 追加角色 ID → 去重保存」，不要直接覆盖用户已有角色；
- 如 Tau 角色需要进入后台文章菜单，再单独补 `role_permission` / `sys_role_menu`；V1 不授予后台菜单，避免越权。

## 7. 错误与边界条件

| 场景 | 处理 |
|---|---|
| token 过期/失效 | 401，前端自动用 refresh token 重签并重试一次 |
| 断网 | 队列保留本地任务，状态 `PENDING`，恢复后重试 |
| 超大文件 | 分块上传；单文件限制建议 200MB（V1），全库配额可配置 |
| 非法路径/文件名 | 服务端白名单校验（禁止 `..`、绝对路径、空名、控制字符） |
| 冲突 | 进入冲突面板，不自动覆盖 |
| 配额超限 | 上传返回 413/配额错误，前端提示扩容或清理历史版本 |
| 服务端磁盘满 | 记录错误，队列挂起并告警 |

## 8. 安全设计

1. JWT 复用现有 `JwtAuthenticationFilter`，不新增明文 token 存储；
2. 凭据只存系统钥匙串（macOS Keychain / Windows DPAPI / Linux libsecret），不落文件明文；
3. 文件名/路径白名单 + 长度限制，防路径穿越与存储滥用；
4. 上传校验真实 MIME/扩展名白名单（文本类为主：md/txt/json/yaml/yml/toml/js/ts/py/java/go/rs/c/cpp/html/css/xml/sql/log/ini/conf 等）；
5. 审计日志脱敏（不记 token、不记文件内容）；
6. 删除接口只允许 owner；批量删除/清空需二次确认；
7. 全链路 HTTPS（生产 `note.lizipro.cn`），本地开发允许 HTTP localhost；
8. 私有文件永不落到公开 `/file/**` 静态映射，下载统一走 `GET /miniProgram/cloud/docs/{fileId}` 的鉴权流。

## 9. 部署与回滚

- 后端新增接口/表后按 lizi 既有发布链路执行：`mvn -pl lizi-server -am -DskipTests package` 生成 jar（生产 jar 为 `lizi-learning-1.0.0.jar`，部署路径 `/usr/local/runtime/`）→ 1Panel 上传 → 重启 → `/lizi/v3/api-docs` 200 + 接口路由验证；
- DDL 先执行 `sql/20261024174525300_add_user_document_tables.sql`（幂等）再发版；
- 回滚：删除新增 DDL 外的功能由代码开关关闭；历史表/版本表保留，不影响既有功能；
- Tau 侧发布：先 Web 版验证登录/同步，再 Tauri 打包；回滚只回 Tau 版本，不影响服务端数据。

## 12. 风险与待决策

1. **账号绑定范围**：Tau 登录是否仅限已注册小程序用户，还是开放独立账号密码登录；建议 P0 复用现有账号体系，P2 再评估独立账号。
2. **存储介质**：V1 磁盘 vs V2 对象存储（MinIO/OSS）切换点，建议一开始就把 `DocumentStorage` 抽象成 SPI。
3. **配额来源**：是否与会员体系联动（普通用户 1GB / 会员 10GB），待产品确认。
4. **同步冲突合并**：文本三路合并仅支持文本类文件；二进制文件冲突只提供覆盖选择。
5. **隐私**：云端文档内容对运营/后台可见性、加密存储策略待确认。
6. **角色账户形态**：建议每个 Tau 账号绑定「Tau 作者」角色，保留作者归属与「我的文章」；如果业务确实要求单一共享「Tau 账号」，需额外设计文章 owner 映射与多人权限，不能直接共用同一账号。
7. **双端渠道控制**：V1 发布即博客+小程序双端可见；如果后续需要分别勾选渠道，按 `article.publish_channels` 增加查询条件，不改发布主流程。
